Where possible, maintenance is shown by the **npm / crates.io / PyPI latest-release date**, queried directly from the registries the same day. ## 1. Are there official Anthropic skills relevant to SVG / vector / visual art, and what do they output?

### Takeaway
Yes, there are official visual-art skills, but **none of them produces SVG**. `canvas-design` outputs PNG/PDF, `algorithmic-art` outputs p5.js HTML/JS, `slack-gif-creator` outputs raster GIFs drawn with PIL, and `theme-factory` and `frontend-design` give styling and design direction only. For SVG work they help as aesthetic guidance. The real SVG tooling has to come from community skills, MCP servers and CLI tools. `skill-creator` is the official way to write your own SVG skill.

### Cited Findings
- `anthropics/skills`: **182,158 stars**, created 2025-09-22. It describes itself as demonstration/educational ("provided for demonstration and educational purposes only") — [README](https://github.com/anthropics/skills)
- Install in Claude Code (verbatim): `/plugin marketplace add anthropics/skills`, then `/plugin install example-skills@anthropic-agent-skills` (or `document-skills@anthropic-agent-skills`) — [README](https://github.com/anthropics/skills)
- The `example-skills` plugin bundles: algorithmic-art, brand-guidelines, canvas-design, doc-coauthoring, frontend-design, internal-comms, mcp-builder, skill-creator, slack-gif-creator, theme-factory, web-artifacts-builder, webapp-testing. Other plugins in the marketplace: document-skills (xlsx/docx/pptx/pdf), claude-api, academy-guide, discernment-nudge — [marketplace.json](https://github.com/anthropics/skills/blob/main/.claude-plugin/marketplace.json)
- **canvas-design**: "Create beautiful visual art in .png and .pdf documents using design philosophy… Output only .md files, .pdf files, and .png files." It works in two steps: (1) write a design-philosophy .md, (2) express it on a canvas as PDF/PNG — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/canvas-design/SKILL.md)
- **algorithmic-art**: "Creating algorithmic art using p5.js with seeded randomness and interactive parameter exploration… Output .md files (philosophy), .html files (interactive viewer), and .js files." Claude must Read `templates/viewer.html` and keep its fixed sections rather than "Creating HTML from scratch" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/algorithmic-art/SKILL.md)
- **slack-gif-creator**: produces raster GIFs with PIL `ImageDraw` primitives and a `GIFBuilder`. Constraints: emoji 128x128, message 480x480, 48–128 colors, emoji GIFs under 3 s — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/slack-gif-creator/SKILL.md)
- **theme-factory**: "10 pre-set themes with colors/fonts that you can apply to any artifact… or can generate a new theme on-the-fly" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/theme-factory/SKILL.md)
- **frontend-design**: "Guidance for distinctive, intentional visual design… aesthetic direction, typography" — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md). It is also shipped as a plugin in the official directory (`frontend-design`, `./plugins/frontend-design`) — [claude-plugins-official marketplace.json](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json)
- **brand-guidelines** applies Anthropic's own brand colors/typography. It is only relevant if you want the Anthropic look — [SKILL.md](https://github.com/anthropics/skills/blob/main/skills/brand-guidelines/SKILL.md)
- `anthropics/claude-plugins-official` ("Official, Anthropic-managed directory"): **43,081 stars**, 315 plugins. The visual/vector-adjacent entries are `figma` (source figma/mcp-server-guide), `playwright` (Microsoft), `chrome-devtools-mcp`, `canva`, `miro`, `adobe-for-creativity` (adobe/skills), `superdesign`, `playground` (interactive single-file HTML playgrounds), `hyperframes` (HeyGen HTML→video with GSAP) and `frontend-design`. The directory has **no** draw.io, Excalidraw, Mermaid, Iconify or SVGO plugin — [marketplace.json](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json)
- In curated lists the only image/visual entries are canvas-design, slack-gif-creator, `imagen` (Gemini image API) and `web-asset-generator`. ComposioHQ/awesome-claude-skills and travisvn/awesome-claude-skills (badge "updated Feb 2026") list **no SVG-specific skills** — [ComposioHQ list](https://github.com/ComposioHQ/awesome-claude-skills); [travisvn list](https://github.com/travisvn/awesome-claude-skills)

### Inferences
- For SVG output, use `frontend-design` and `theme-factory` as *style* inputs (palette, typography), paired with an SVG-producing skill (section 2) and a renderer (section 4).
- `canvas-design`'s "design philosophy first, then execute" pattern carries over to logos and illustrations. The community `logo-design` skill (section 2) does essentially this, adding SVG-specific tests.
- To build an in-house SVG skill, use `skill-creator`, which ships in `example-skills`.

### Gaps
- I found no official Anthropic SVG-specific skill and no official statement on Claude's SVG capability. The Anthropic engineering blog was not reachable for fetching.

## 2. Which community skills target SVG, logos, icons and diagrams, and which are high quality?

### Takeaway
The strongest community SVG skills share one feature: a **render → look at PNG → fix** loop with tooling built in. The best picks by signal and quality: **kaankiziltug/logo-design-skill** (logos; Claude Code plugin; audit and test-sheet tools), **coleam00/excalidraw-diagram-skill** (diagrams with a Playwright render check), **yctimlin/mcp_excalidraw** (skill + CLI + MCP, headless resvg renders), the **official greensock/gsap-skills** (SVG animation) and **LottieFiles/motion-design-skill** (motion principles). The general-purpose `svg-creator-skill` has the right methodology, but it is small and hard-codes Claude.ai paths.

### Cited Findings
**Logos / illustrations / generic SVG**
- **kaankiziltug/logo-design-skill**: **3,745 stars**, created 2026-09-26, so it is very new and growing fast; it has CI tests. Its scope runs from brief and concepts to "production-ready SVG files", with a **1,400+ real-world SVG logo** reference library. Its dependency-free Python tools audit SVGs, build test sheets ("16 px pixel test, one-colour, reversed, squint, mirror… competitor shelf test"), render PNGs and export favicon/app-icon/web-manifest sets. The workflow "always stops at the checkpoint" after 3 concepts — [README](https://github.com/kaankiziltug/logo-design-skill)

  - Example tool calls: `python3 scripts/render_png.py my-logo.svg --size 512 -o my-logo.png`, `python3 scripts/export_variants.py my-logo.svg --mono "#0F7C80" --icon-bg "#0F7C80" --web-icons`. PNG export uses "whatever renderer is available: cairosvg, rsvg-convert, Inkscape, a Chromium-based browser… or macOS Quick Look". It requires a model that can view images, "because it renders its own drafts to PNG and checks them" — [README](https://github.com/kaankiziltug/logo-design-skill)

The workflow is mandatory: "WRITE SVG → RENDER → VIEW PNG → ASSESS → FIX… The script REFUSES to deliver if you never rendered". Techniques include 4–8-stop gradients, "five-zone lighting", colored (not black) shadows, CSS animation with `transform-box: fill-box`, SMIL for `<img>`-embeddable SVGs, and an always-included reduced-motion media query. Expect 2–8 iterations, and 5–8 for characters — [README](https://github.com/upbrew-tech/svg-creator-skill); [SKILL.md](https://github.com/upbrew-tech/svg-creator-skill/blob/main/SKILL.md)

Manual install: `cp -r svg-creator-skill ~/.claude/skills/svg-creator` — [README](https://github.com/upbrew-tech/svg-creator-skill); [SKILL.md](https://github.com/upbrew-tech/svg-creator-skill/blob/main/SKILL.md)

## 3. Which MCP servers are best for vector/diagram work, and which actually exist and are maintained?

### Takeaway
Verified and maintained in Oct 2026:
- **Official draw.io**: `jgraph/drawio-mcp`, with a Claude Code plugin, npm `@drawio/mcp` and a hosted `https://mcp.draw.io/mcp`. Very active: npm release 2026-10-18.
- **Official Excalidraw MCP App**: `excalidraw/excalidraw-mcp` at `https://mcp.excalidraw.com`. It is a chat widget, so for coding agents **yctimlin/mcp_excalidraw** is better.
- **Official Figma**: `claude plugin install figma@claude-plugins-official`, which serves SVG assets.
- **Recraft**: the local `recraft-ai/mcp-recraft-server` is **deprecated and archived**. Use the remote `https://mcp.recraft.ai/mcp` (OAuth).
- **Mermaid**: `veelenga/claude-mermaid` (Claude Code plugin with live preview) or `hustcc/mcp-mermaid`.
- **Icons**: there is **no official Iconify or Lucide MCP**. The best community options are `iconify-mcp-server` (imjac0b), `lucide-icons-mcp` (SeeYangZhi) and `aria-icons`.
- **Inkscape**: community MCPs only, all under 100 stars.

### Cited Findings
**draw.io / diagrams.net (official, by jgraph)**
- `jgraph/drawio-mcp`: **5,660 stars**, created 2026-02-02. npm `@drawio/mcp` latest **1.10.0, published 2026-10-18**. "The official draw.io MCP… server" — [README](https://github.com/jgraph/drawio-mcp); [npm](https://www.npmjs.com/package/@drawio/mcp)
- It offers four approaches: (1) **MCP App Server**, hosted at `https://mcp.draw.io/mcp`, which renders inline in hosts with MCP Apps support. - Claude Code plugin (verbatim): `/plugin marketplace add jgraph/drawio-mcp`, then `/plugin install drawio@drawio`. ## 4. What is the best workflow for producing high-quality SVG with Claude Code (render-and-look loop, SVGO pitfalls, accessibility, currentColor, sprites, SVGR)?

### Takeaway
Treat Claude as a strong SVG *coder* but an unreliable *visual judge* until it looks at its own output. Every high-quality skill above enforces **write → rasterize (resvg / rsvg-convert / Playwright) → Read the PNG → fix**. Then optimize with **SVGO v4**, which no longer strips `viewBox`/`<title>` by default. Protect IDs needed by CSS, JS or animation from `cleanupIds`. Add `role="img"` + `<title>`/`aria-labelledby`, or `aria-hidden` for decorative graphics. Convert to React with SVGR when needed.

### Inferences
- **Recommended Claude Code loop** (synthesized from the skills above):
  1. Ask for SVG with an explicit `viewBox`, a fixed palette, named `id`s and groups for parts you will animate.
  2. Render with `resvg in.svg out.png -w 512` (or `rsvg-convert -w 512 in.svg -o out.png`).
  3. Have Claude `Read` the PNG, list concrete defects, and fix.
  4. Repeat 2–8 times.
  5. For animated SVGs, resvg cannot render motion. Use Playwright or Chrome DevTools MCP to screenshot at several timestamps, or pause the animation via CSS.
  6. Run `svgo --multipass` with a config that keeps `viewBox` and `<title>` and preserves animation and CSS-hook IDs (`cleanupIds: { preserve: [...] }` or `preservePrefixes`).
  7. Re-render after SVGO to confirm nothing changed visually.
- **currentColor** (prior knowledge, not re-verified in this session): set `fill="currentColor"` or `stroke="currentColor"` on icons so they inherit CSS `color` for theming and dark mode. Ask Claude to replace hard-coded hex values in monochrome icons. SVGO's `convertColors` can be configured with `currentColor: true` for this; verify the plugin params in the SVGO docs.
- **Sprites** (prior knowledge): for many icons, combine them into one `<svg>` with `<symbol id="icon-x" viewBox>` and use `<use href="#icon-x">`. Run SVGO per icon *before* building the sprite, and use `prefixIds` to avoid ID collisions (gradients/clipPaths) when inlining several SVGs into one page.
- **SVGO pitfalls for animation**: default `cleanupIds` (renaming), `collapseGroups`, `moveGroupAttrsToElems`, `convertShapeToPath` and `mergePaths` can destroy the element structure and selectors that GSAP or CSS animations target. For animated or interactive SVGs, disable these via `overrides`, or optimize only the static parts.
- SVGR's stalled release cadence (8.1.0 in 2023) suggests that in new Vite/Next projects you should check SVGR's current status, or inline the SVG as JSX by hand with Claude, instead of assuming SVGR keeps pace with SVGO v4 defaults.
- For text-heavy SVGs (logos with type), resvg's lack of native text rendering and its font fallback can differ from browsers. Convert text to paths for final logo deliverables, and verify in a browser screenshot.
