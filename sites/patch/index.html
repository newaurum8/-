Как Patch встраивается в процесс
Ничего не меняется для разработчиков. Patch приходит в PR как ещё один ревьюер, только быстрый.

  
  

    
Понимает проект целиком
Индексирует репозиторий и знает, что функция из PR вызывается в 14 местах. Поэтому не ругается на «неиспользуемую» переменную, которая нужна соседнему модулю.

    
Правит, а не ноет
К каждой находке готовый diff. Нажали «Применить», Patch закоммитил в ту же ветку и прогнал тесты.

    
Учится на ваших ревью
Замечания, которые команда отклоняет, Patch перестаёт повторять. Через месяц он говорит на языке вашего стайлгайда.

    
Безопасность по умолчанию
OWASP Top 10, секреты в коде, зависимости с CVE. Критичные находки блокируют мерж, если вы так настроите.

Вопросы

  
Код уходит на сторону?
В облачной версии анализ идёт в изолированном окружении и не используется для обучения. Для Enterprise есть self-hosted, код не покидает вашу сеть.

  
Чем Patch отличается от линтера?
Линтер проверяет синтаксис по правилам. Patch понимает намерение: видит, что вы считаете деньги во float, что токен попадёт в логи, что цикл сделает 400 запросов вместо одного.

  
Какие языки?
TypeScript, JavaScript, Python, Go, Java, Kotlin, C#, PHP, Ruby, Rust. Остальные в бете.

  
Будет ли спамить комментариями?
Нет. По умолчанию Patch оставляет не больше 5 комментариев на PR, остальное сворачивает в отчёт. Порог настраивается.
