# Лабораторная проверка переписала визуальные рецепты Claude Code

К октябрю 2026 года лучший набор для визуальной работы в Claude Code по-прежнему небольшой и почти целиком вендорский. Результат определяет не число скилов, а замкнутый цикл «отрендерить → посмотреть PNG → исправить». **Фронтенд:** `frontend-design`, документация под версию фреймворка (свои MCP и скилы теперь есть у Svelte, Angular, Nuxt, Astro, Expo и React Router), скил shadcn, один браузерный инструмент (Playwright CLI или MCP) и Chrome DevTools MCP для производительности. **SVG и 2D:** генерация кодом с растровой самопроверкой через resvg и SVGO v4 с исправленным конфигом; из новинок — QuiverAI для AI-вектора и SVGator для анимации. **Видео и аудио:** Remotion (теперь с официальным плагином) или HyperFrames, а монтаж, звук и субтитры — через Bash с ffmpeg, auto-editor и WhisperX; у DaVinci Resolve Studio 21.1 появился официальный встроенный MCP. **3D:** MCP for Blender или официальный Blender Lab MCP, CoplayDev для Unity, генератор конфигурации в UE 5.8, PlayCanvas для веб-движка и build123d для CAD. Проверка в контейнере на Claude Code 2.1.303 подтвердила синтаксис `claude plugin` и `claude mcp`, но нашла ошибки примерно в десяти рецептах первого отчёта. Команда Vercel молча теряет React-скил, «щадящий» конфиг SVGO удаляет id анимаций и блок `prefers-reduced-motion`, контакт-лист ffmpeg падает на клипах длиннее 80 секунд. `--disable-gpu` в Chromium 141 WebGL не ломает, а `claude plugin install` из терминала ставит плагин без панели стоимости. Независимых доказательств пользы дизайн-скилов почти нет. AI-судьи Skill Arena ставят три вкусовых скила вровень, а академический SkillsBench даёт скилам в среднем +16 п. п., но фиксирует ухудшение примерно на каждой пятой задаче. Поэтому ставить нужно выборочно: 38 популярных скилов вместе с плагинами Figma и HyperFrames занимают около 9,9 тыс. токенов постоянно, а бюджет списка скилов порядка 2 тыс. Цифры по безопасности тоже уточнились. Подтверждённо вредоносных скилов в выборке Snyk 76, а не 1 467. Зато рекомендованный для фронтенда Context7 получил критическую CVE-2026-75130, а Claude Code хранит MCP-заголовки и OAuth-токены открытым текстом в `~/.claude.json`.

## Контейнер подтвердил синтаксис CLI, но опроверг десяток рецептов первого отчёта

Все команды первого отчёта, которые можно было безопасно выполнить, 19 октября 2026 года прогнали в Linux-контейнере. Окружение: Claude Code 2.1.303, Node 22.22, CLI `skills` 1.7.2, ffmpeg 6.1.1 из Ubuntu, Playwright 1.56.1 с Chromium 141. Каждая команда, которая могла записать конфигурацию, запускалась с временным `HOME` и выключенной телеметрией (`DISABLE_TELEMETRY=1 DO_NOT_TRACK=1`). MCP-серверы не запускались, скрипты из скилов не исполнялись, установщики вида `curl | sh` не использовались. Отсюда **четыре метки**, которые стоят у команд ниже. `[лаб.]` — команда выполнена, вывод проверен. `[лаб.: принято]` — CLI приняла команду и записала конфигурацию, но сам сервер не стартовал, поэтому его работоспособность не доказана. `[README]` — команда дословно взята из документации вендора, но не запускалась. `[выведено]` — команда собрана по общему синтаксису Claude Code; перед использованием сверьте её с `--help`.

Большая часть механики подтвердилась. Команды `claude plugin install …@… --scope project`, `claude plugin marketplace add`, `claude mcp add --transport http`, `claude mcp add-json` и опции после позиционного имени завершились с кодом 0. Все 13 команд `claude mcp add` из первого отчёта CLI приняла. Официальный маркетплейс действительно содержит **315 плагинов**, `anthropics/skills` регистрируется как `anthropic-agent-skills`, у Remotion 12 скилов, у threejs-skills 13. Подтвердилось и правило про `-pix_fmt yuv420p`: без него RGB-источник кодируется в профиль «High 4:4:4 Predictive» вместо обычного High [лаб.]. Рендер Rust-бинарником resvg 0.48.1 принимает синтаксис первого отчёта `resvg logo.svg logo.png -w 512`. А вот npm-пакет `@resvg/resvg-js-cli` — бета 2024 года, и он отвечает на `-w` ошибкой `Unkonw option`: у него флаг `--fit-width` ([resvg](https://github.com/linebender/resvg)).

### Как на самом деле раскладывает файлы `npx skills add`

Внутри Claude Code CLI `skills` определяет агента по переменной окружения (`AI_AGENT=claude-code_2-1-303_agent`) и ставит без вопросов. Но раскладка на диске та же, что и при ручном запуске. Без `-a` он объявляет «Installing to all agents» для 79 агентов. Затем пишет настоящую копию в `./.agents/skills/<name>`, относительный симлинк `./.claude/skills/<name> -> ../../.agents/skills/<name>`, отдельную копию в `./agent/skills/` для агента Eve и файл `skills-lock.json`. Для 12 скилов Remotion это **3,5 МБ в `.agents` и ещё 3,5 МБ в `agent/`**, а `.claude/skills` создаётся даже в пустом каталоге без `.git`. Claude Code получает именно симлинк, потому что в таблице агентов CLI у него `skillsDir: ".claude/skills"`. Его собственный валидатор подтверждает: «A session loading this directory does follow them». Глобальная установка без `-a` хуже: в чистом `$HOME` команда `npx skills add greensock/gsap-skills --skill gsap-core -g -y` создала **54 симлинка и 53 новых dot-каталога** (`.adal`, `.aider-desk`, `.trae` и так далее). С `-a claude-code` получаются обычные копии в `.claude/skills/` или `~/.claude/skills/` и файл блокировки, больше ничего [лаб.]; ([vercel-labs/skills](https://github.com/vercel-labs/skills)).

Две особенности CLI стоит закладывать в скрипты. Первая: `-l` перечисляет скилы и ничего не пишет на диск, но вместе с `--json` падает с ошибкой «The --json flag cannot be combined with --list». Вторая: опечатка в одном из нескольких `--skill` не вызывает ошибки. Команда с одним неверным именем завершается с кодом 1 и сообщением `No matching skills found`, а та же опечатка рядом с верным именем молча даёт код 0 и ставит только верный скил. Отсюда правило для CI: каждую многоскиловую строку сначала прогоняйте с `-l`. Ещё одно следствие относительных симлинков: если команда коммитит только `.claude/`, у коллег и на Windows ссылки сломаются. Это вывод из наблюдаемой раскладки, на Windows его не проверяли. CLI Remotion работает только внутри Remotion-проекта и вызывает закреплённый `skills@1.7.0`. А `playwright-cli install --skills` кроме скила ещё и скачивает Chromium, если не нашёл Chrome или Edge и не задан `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` [лаб.]; ([Playwright CLI README](https://github.com/microsoft/playwright-cli/blob/main/README.md)).

```bash
npx skills add <owner/repo> -l                                            # [лаб.] точные имена, без записи на диск
npx skills add <owner/repo> --skill <a> --skill <b> -a claude-code -y     # [лаб.] копии только в ./.claude/skills
npx skills add <owner/repo> --skill <a> -g -a claude-code -y              # [лаб.] глобально в ~/.claude/skills
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npx -y @playwright/cli@0.1.22 install --skills   # [лаб.] скил в .claude/skills/playwright-cli
```

### Что пишут на диск `claude plugin` и `claude mcp`

Проект-scope пишет в `./.claude/settings.json` (`enabledPlugins`, а если маркетплейс добавлен с `--scope project`, то и `extraKnownMarketplaces`) и в `./.mcp.json`. User-scope и local-scope пишут в `~/.claude/settings.json`, в `~/.claude/plugins/*` и в `~/.claude.json`. Local-серверы лежат в `projects["<абсолютный путь>"].mcpServers`, user-серверы — в верхнеуровневом `mcpServers`. Сами плагины кэшируются в `~/.claude/plugins/cache/<marketplace>/<plugin>/<версия>/`. Для плагинов внутри репозитория маркетплейса версия — короткий git SHA, для плагинов-ссылок — номер пакета (`figma/2.2.157`, `chrome-devtools-mcp/1.11.0`). Встроенный маркетплейс `anthropic-plugin-directory` присутствует всегда, даже если ничего не добавлять. Маркетплейс HyperFrames из собственного репозитория предупреждает, что 84 файла пришли как указатели Git LFS, и предлагает `git -C …/marketplaces/hyperframes lfs pull` [лаб.]; ([Settings reference](https://code.claude.com/docs/en/settings-reference)).

Главная практическая находка этого блока — безопасный аудит до установки. `claude plugin details <name>` работает только для уже установленного плагина. Зато `claude --plugin-dir <каталог плагина> plugin details <name>` показывает состав и стоимость любого скачанного плагина. При этом MCP-серверы он **не запускает**: фиктивный плагин с сервером `/bin/sh -c "date >> mcp_spawned.log"` был показан как «tool schemas resolved at runtime; not counted», а лог так и не появился [лаб.]; ([Plugin security](https://code.claude.com/docs/en/plugins/security)). Учтите, что стоимость схем MCP-инструментов в эту оценку не входит. Транспорт SSE при добавлении не вызывает никаких предупреждений, хотя объявлен устаревшим. Начиная с v2.1.265 `--transport http` сам откатывается на SSE, поэтому для серверов с адресом `/sse` сначала пробуйте HTTP ([Claude Code: MCP](https://code.claude.com/docs/en/mcp)).

```bash
# Аудит до установки: состав и стоимость, без запуска MCP-серверов
claude plugin marketplace add anthropics/claude-plugins-official                   # [лаб.] клон в ~/.claude/plugins/marketplaces/
claude --plugin-dir ~/.claude/plugins/marketplaces/claude-plugins-official/plugins/frontend-design \
  plugin details frontend-design                                                   # [лаб.] Always-on ~80, on-invoke ~2.7k
# Установка для команды: пишет enabledPlugins в ./.claude/settings.json
claude plugin install frontend-design@claude-plugins-official --scope project      # [лаб.]
# Секреты только через переменные: строка ${VAR} хранится как есть и раскрывается при запуске
claude mcp add-json meshy '{"command":"npx","args":["-y","@meshy-ai/meshy-mcp-server"],"env":{"MESHY_API_KEY":"${MESHY_API_KEY}"}}' --scope project   # [лаб.: принято]
```

## Полный набор скилов съедает 10 тысяч токенов при бюджете около двух тысяч

Стоимость скилов в контексте измерили двумя способами. Первый — собственным скриптом (символы / 4). Второй — оценщиком самого Claude Code: каждый набор скилов копировали в минимальный плагин-обёртку и запускали `claude --plugin-dir <обёртка> plugin details`. «Постоянно» — это строка из списка скилов в каждой сессии, «при вызове» — тело SKILL.md, которое загружается при срабатывании [лаб.].

| Набор (способ установки) | Скилов | Постоянно, токенов | При вызове, токенов | Особенности |
|---|---|---|---|---|
| `frontend-design` (официальный маркетплейс) | 1 | ~80 | ~2,7 тыс. | SKILL.md 9 390 байт |
| `remotion-dev/skills` | 12 | ~299 всего | от ~220 до ~6,4 тыс. | 271 файл, 2,3 МБ; ключ `version` во frontmatter |
| `vercel-labs/agent-skills` (2 скила) | 2 | ~202 | 2,6 тыс. и ~360 | `web-design-guidelines` тянет правила по сети |
| `shadcn/ui` | 2 | ~276 | ~8 тыс. и ~3,5 тыс. | ключ `user-invocable`; `allowed-tools` через запятую |
| `cloudai-x/threejs-skills` | 13 | **~1 524** | **7,4–12,4 тыс.** | тела по 236–497 строк |
| `greensock/gsap-skills` | 8 | **~1 127** | 1,6–8,6 тыс. | |
| `playwright-cli` | 1 | ~44 | ~5,8 тыс. | |
| плагин `figma` | 16 | **~2 419** | 570–13,7 тыс. | плюс MCP-сервер |

| плагины `context7`, `playwright` | 0 | ~0 | — | только MCP |

Из таблицы следуют три вывода. Первый: «около 100 токенов на скил» в среднем верно, но наборы складываются. 38 скилов из первых шести строк стоят около **3,5 тыс. постоянных токенов**, а вместе с плагинами Figma и HyperFrames — около **9,9 тыс.** Список скилов в Claude Code ограничен **1 % окна контекста**, то есть примерно 2 тыс. токенов на окне в 200 тыс. При переполнении первыми выбрасываются описания скилов, которые вызываются реже всего ([Claude Code: Skills](https://code.claude.com/docs/en/skills)). Считает ли бюджет токены или символы, проверка не выяснила. Второй вывод: дороже всего обходится срабатывание. Один скил three.js при вызове добавляет около 10 тыс. токенов, а `talking-head-recut` из HyperFrames — 22,6 тыс. Третий: формула «символы / 4» занижает стоимость кода в SKILL.md в **1,15–1,66 раза**, поэтому бюджет считайте через `plugin details`, а не на глаз. Ни одно описание не подошло к пределу спецификации в 1 024 символа. Однако все 13 тел threejs-skills больше рекомендованных спецификацией «< 5000 tokens», хотя и укладываются в 500 строк ([спецификация Agent Skills](https://github.com/agentskills/agentskills/blob/main/docs/specification.mdx)). Нестандартные ключи `version` (у Remotion) и `user-invocable` (у shadcn) Claude Code принимает без ошибок. Будут ли они отвергнуты при загрузке в claude.ai или API, проверить не удалось [лаб.].

Тратить контекст стоит только на то, что окупается, и независимые данные это подтверждают. SkillsBench (arXiv 2602.12670, постер NeurIPS 2026: 84 задачи, 7 конфигураций агентов, 7 308 траекторий) показал, что курированные скилы поднимают средний pass rate на **+16,2 п. п.** Но разброс огромный: от **+4,5 п. п. в программной инженерии** до +51,9 п. п. в медицине. На **16 из 84 задач** результат ухудшился, сгенерированные самим агентом скилы пользы не дали, а сфокусированные скилы из 2–3 модулей обошли исчерпывающую документацию ([arXiv 2602.12670](https://arxiv.org/html/2602.12670v1); [NeurIPS](https://neurips.cc/virtual/2026/poster/139353)). Для визуальной работы это означает простую вещь: ставьте узкие скилы под свою задачу через `--skill`, а не весь пакет. Superdesign, сам продающий конкурирующий продукт, формулирует то же короче: «pick one taste skill, not all four… stacking them mostly burns context» ([superdesign.dev](https://superdesign.dev/blog/design-skills-reviewed)).

Со стороны MCP картина другая. Tool search в Claude Code включён по умолчанию, поэтому определения инструментов почти не стоят ничего, пока не нужны. Например, 130 инструментов PlayCanvas занимают около 43 тыс. токенов схем, а при старте загружаются только их имена, около 1 тыс. ([playcanvas/editor-mcp-server](https://github.com/playcanvas/editor-mcp-server)). Расходуют контекст ответы: предупреждение появляется на 10 тыс. токенов, потолок по умолчанию — 25 тыс. (`MAX_MCP_OUTPUT_TOKENS`) ([Claude Code: MCP](https://code.claude.com/docs/en/mcp)). Больше всего стоят картинки. Изображение обходится в `⌈w/28⌉×⌈h/28⌉` визуальных токенов: скриншот 1920×1080 на моделях 4.7 и новее — **около 2 691 токена**, потолок 4 784 при длинной стороне 2 576 px. Если в запросе больше 20 картинок, действует более жёсткий лимит 2 000 px на сторону ([Platform: Vision](https://platform.claude.com/docs/en/build-with-claude/vision)). Двенадцать скриншотов (три брейкпоинта на четыре маршрута) — это уже ~32 тыс. токенов, и все они пересылаются с каждым следующим запросом.

```bash
# Оценка своего набора (методика проверки; plugin.json минимальный)   [выведено]
mkdir -p /tmp/wrap/.claude-plugin && cp -r .claude/skills /tmp/wrap/skills
echo '{"name":"wrap","description":"budget check"}' > /tmp/wrap/.claude-plugin/plugin.json
claude --plugin-dir /tmp/wrap plugin details wrap        # Always-on и on-invoke по каждому скилу
# В сессии: /skill-doctor (стоимость и частота вызовов, v2.1.252+), /context (что загружено)
```

Скилы, которые нужны редко, можно оставить в списке только по имени. Для этого в `settings.json` задаётся `"skillOverrides": {"threejs-postprocessing": "name-only", "gsap-utils": "off"}`; допустимые состояния: `on`, `name-only`, `user-invocable-only`, `off`. На скилы из плагинов `skillOverrides` не действует, их отключают вместе с плагином ([Claude Code: Skills](https://code.claude.com/docs/en/skills)). У Remotion описания скилов очень короткие, 23–47 символов («Export a Remotion video», «Router for all Remotion skills»). Похоже, они рассчитаны на явный вызов через маршрутизатор `/remotion-best-practices`, а не на автоматическое срабатывание. Это вывод, в живой сессии его не проверяли [лаб.].

## Фронтенд: вкус задают инструкции, а качество — скриншот и детерминированная проверка

### Вкусовые скилы делят первое место, а сильнее всего действуют бриф и уровень effort

Единственное публичное сравнение «со скилом и без» выглядит впечатляюще, но доказывает меньше, чем кажется. В `dani-z/frontend-design-skill-benchmark` три промпта по одному прогону дали **18/18 проверок со скилом против 5/18 без него**, то есть +72 п. п. Только проверки там — это буквально правила самого скила: «Does NOT use Inter, Roboto, Arial, or system-ui», «Does NOT use a purple/violet gradient». Кто оценивал и была ли оценка слепой, README не сообщает ([README](https://github.com/dani-z/frontend-design-skill-benchmark); [eval_metadata.json](https://github.com/dani-z/frontend-design-skill-benchmark/blob/main/iteration-1/eval-0-lumen-landing/eval_metadata.json)). Ирония в том, что выходы «со скилом» (Playfair Display, «warm paper palette `#f5f0e8`») совпадают с тем, что текущий SKILL.md сам называет новым ИИ-клише: «a warm cream background (near #F4F1EA) with a high-contrast serif display and a terracotta accent» ([SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)). Скорее всего, бенчмарк старше переписанной версии. Заодно он иллюстрирует довод скептиков с HN: скил не улучшает дизайн, а заменяет одну узнаваемую манеру другой, «the design version of a rhetorical tic» ([HN 48504912](https://news.ycombinator.com/item?id=48504912); [avoid-ai-design](https://github.com/funboy322/avoid-ai-design)).

Единственная «арена» скилов использует AI-судей и прямо просит считать результаты «directional evidence, not a definitive ranking». Шесть фронтенд-скилов прогнали на Claude Sonnet 5 в трёх задачах, оценивали два слепых AI-судьи; базовой линии без скила в опубликованном фрагменте нет ([happycapy Skill Arena](https://happycapy.ai/skill-arena/frontend-design)).

| Скил | Балл | Комментарий арены |
|---|---|---|
| `frontend-design` (Anthropic) | 8,0 | «most reliable all-rounder», выиграл портфолио и дашборд |
| `design-taste-frontend` (Leonxlnx) | 8,0 | |
| `superdesign` | 8,0 | выиграл SaaS-лендинг |
| `web-design-guidelines` (Vercel) | 6,8 | ревью-скил, а не генератор |
| `ui-ux-pro-max` | 6,7 | |
| `high-end-visual-design` | 6,5 | |

Остальные свидетельства — тесты одного автора, и они сходятся в одном: разница в инструкциях, а не в способностях модели. Bare Metal Digest сравнил claude.ai, «голый» Claude Code и Claude Code с плагином и пришёл к выводу «the gap isn't about capability; it's about instructions» ([Substack](https://baremetaldigest.substack.com/p/the-design-gap-between-claude-web)). Японский автор на трёх проектах дважды предпочёл официальный скил и один раз ui-ux-pro-max и назвал разницу «делом вкуса» ([note.com](https://note.com/ai_smallbiz_lab/n/n64e2c6f8de5a?hl=en)). О ui-ux-pro-max пишут «has potential but needs work», а заявленные «50+ styles» называют преувеличением ([Medium](https://medium.com/@kavita.ux.design/ui-ux-pro-max-i-tried-it-heres-my-take-8b34f992e685)). Оценки 4,7/5 на сайтах-каталогах вероятно аффилиатные ([skiln.co](https://skiln.co/blog/ui-ux-pro-max-skill-review-2026)). Популярность о качестве не говорит: `frontend-design` поставили 767 871 раз против 350 625 у Design Taste Frontend ([Skillselion](https://skillselion.com/design)).

Сильнее скилов действуют две вещи, которые ничего не стоят. Первая — конкретный бриф: «Once I specified the layout, colors, copy, interactions, and responsive behavior, both AI Coding Agents produced very similar results» ([AI Fire](https://www.aifire.co/p/claude-code-codex-which-ai-coding-agent-designs-better)). Вторая — уровень effort. По умолчанию Opus 5.5 в Claude Code работает на `medium`, а `high` документация рекомендует для «Work where verification matters» ([Model config](https://code.claude.com/docs/en/model-config)). AI Fire счёл лучшим балансом качества и скорости уровень `xhigh` ([AI Fire](https://www.aifire.co/p/claude-opus-5-5-built-the-same-app-6-times-and-extra-won)). На Low мобильный экран бронирования получился за минуту и около 1 % дневного лимита, но со стилями по умолчанию ([uxplanet](https://uxplanet.org/i-tested-opus-5-5-at-every-effort-level-for-ui-design-c19860ad8563)). Публичные арены ранжируют модели, а не скилы. В Code Arena WebDev на 23 сентября 2026 года Opus 5.5 (Max) набрал **1818 ±21** против 1792 ±12 у GPT-6 Astra, и лидерство «not statistically settled» ([aiidelist](https://aiidelist.com/blog/claude-opus-5-5-code-arena-webdev)). В тесте Nate Herk Codex выиграл 5 из 6 открытых дизайн-раундов, хотя лучший one-shot дал Claude Code; стоимость — около $42 против чуть меньше $20 ([X](https://x.com/nateherk/article/2092603618000097582)). Практический рецепт сообщества: **один вкусовой скил + один детерминированный проверяльщик + цикл скриншотов**, а пользу проверять собственным A/B-прогоном. Детерминированный проверяльщик есть у Impeccable (Paul Bakaus, Apache-2.0): `npx impeccable detect src/` прогоняет 24–27 правил, плюс LLM-критика по 12 правилам ([docs](https://www.mintlify.com/pbakaus/impeccable)). Учтите, что в каталоге у него пройден только один сканер безопасности из трёх ([skillselion](https://skillselion.com/skills/pbakaus/impeccable)).

### Что на самом деле написано в трёх главных скилах и где они спорят

Копии `frontend-design` в `anthropics/skills`, `anthropics/claude-plugins-official` и `anthropics/claude-code` побайтно одинаковы: 9 390 байт, MD5 `7d6df6b2e98e38f8b86046325dc6afd0`. Устарел только README плагина, который по-прежнему обещает «Bold aesthetic choices… High-impact animations» ([README](https://github.com/anthropics/claude-code/blob/main/plugins/frontend-design/README.md)). Из-за него блоги до сих пор описывают скил как «смелую эстетику», поэтому читайте SKILL.md, а не README. Текущий текст требует обратного: «Spend your boldness in one place». Он запрещает дежурные приёмы («fade-and-slide-up entrances on each section and hover transitions on every card are the generic default and read as AI-generated») и просит сначала определить, что за продукт, и подтвердить это с клиентом. Работа идёт в два прохода: план из 4–6 именованных hex-цветов с ASCII-вайрфреймом, затем его критика относительно брифа. Минимальная планка — «responsive down to mobile, visible keyboard focus, reduced motion respected». Отдельно сказано про скриншоты: «a picture is worth 1000 tokens». Тексты интерфейса — «sentence case, no filler», «'Save changes,' not 'Submit.'» ([SKILL.md](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)).

`web-design-guidelines` от Vercel — это загрузчик на 1 231 байт. При каждом запуске он через WebFetch скачивает правила из `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md` и выдаёт находки в формате `file:line` [лаб.]; ([SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/web-design-guidelines/SKILL.md)). Значит, ему нужны сеть и разрешение на WebFetch, а результаты могут меняться между прогонами. Для воспроизводимого ревью в CI держите в проекте закреплённую копию `command.md`. Сами правила полезны и конкретны: «Icon-only buttons need `aria-label`», «Never `outline-none` / `outline: none` without focus replacement», «Never `transition: all`», «`<img>` needs explicit `width` and `height`», «Large lists (>50 items): virtualize» ([command.md](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)). Но одно правило прямо противоречит `frontend-design`: «Title Case for headings/buttons (Chicago style)» против sentence case. Если не указать в CLAUDE.md, какой стиль главный, ревью-проход будет «исправлять» то, что вкусовой скил сделал намеренно. `vercel-react-best-practices` — это 70 правил в 8 категориях, упорядоченных по влиянию. Критичны водопады запросов и размер бандла; например, `import { Check, X, Menu } from 'lucide-react'` «Loads 1,583 modules, takes ~2.8s extra in dev». Его сводный AGENTS.md весит 108 261 байт, поэтому агенту нужно читать отдельные `rules/*.md`, а не весь файл. Категория `server-*` к SPA на Vite почти не относится ([SKILL.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/react-best-practices/SKILL.md); [AGENTS.md](https://github.com/vercel-labs/agent-skills/blob/main/skills/react-best-practices/AGENTS.md)).

### Документация под установленную версию важнее общего MCP

Главный сдвиг 2026 года во фронтенде: вендоры начали поставлять документацию и скилы вместе с пакетом, под точную версию. Next.js кладёт доки в `node_modules/next/dist/docs/`, React Router — свой скил в репозиторий, TanStack Intent подтягивает скилы из установленных npm-пакетов, у Angular есть `ng mcp` прямо в CLI. Где так сделано, это точнее Context7, потому что совпадает с установленной версией ([remix-run/agent-skills](https://github.com/remix-run/agent-skills); [TanStack/intent](https://github.com/TanStack/intent); [Angular MCP](https://github.com/angular/angular/blob/main/adev/src/content/ai/mcp-server-setup.md)).

| Фреймворк | Что ставить | Команда | Метка |
|---|---|---|---|

| Svelte | плагин `svelte`: MCP, LSP, субагент `svelte-file-editor`, скилы `svelte-code-writer` и `svelte-core-bestpractices` | `/plugin marketplace add sveltejs/ai-tools`, затем `/plugin install svelte@svelte` | [выведено из marketplace.json] |

У каждой строки есть свои ловушки. `.mcp.json` плагина Svelte запускает локальный `npx -y @sveltejs/mcp`, а не удалённый URL, поэтому в облачных сессиях лучше `https://mcp.svelte.dev/mcp`. Плагин Expo уже регистрирует сервер, и повторный `claude mcp add` создаст дубликат. Локальные возможности Expo требуют SDK 54+, работают только с iOS-симуляторами на macOS и после каждого перезапуска dev-сервера требуют переподключить MCP. Требует ли Expo платный план, источники противоречат друг другу ([mcp.mdx](https://github.com/expo/expo/blob/main/docs/pages/mcp.mdx)). Описание репозитория TanStack CLI всё ещё упоминает MCP, но в пакете 0.72.0 такой команды нет, а телеметрия включена по умолчанию (`TANSTACK_CLI_TELEMETRY_DISABLED=1`) ([TanStack/cli](https://github.com/TanStack/cli)). Vue-скилы срабатывают нестабильно, и README советует начинать промпт со слов «use vue skill» ([vuejs-ai/skills](https://github.com/vuejs-ai/skills)). Для всего, что не покрыто, остаётся Context7, но с учётом CVE-2026-75130 из раздела о безопасности.

### Браузерные инструменты сравнялись по токенам, выбирать стоит по возможностям

Знаменитое сравнение «Playwright MCP ~114 тыс. токенов на задачу против ~27 тыс. у CLI» относится к инструментам начала 2026 года, и даже его авторство разные источники указывают по-разному ([Better Stack](https://betterstack.com/community/guides/ai/playwright-cli-vs-mcp-browser/)). С апреля 2026 года Playwright MCP пишет accessibility-снимок в файл и возвращает путь ([issue #1548](https://github.com/microsoft/playwright-mcp/issues/1548)). Повторный тест `@playwright/mcp@0.0.78` против `@playwright/cli@0.1.17` на сценарии «логин → дашборд» показал разницу около 1 % (≈3 580 против ≈3 620 символов). Оставшийся разрыв — это ~24 определения инструментов, примерно 18 тыс. символов ([dev.to](https://dev.to/aswani25/playwright-cli-vs-playwright-mcp-which-should-you-use-with-claude-code-1olh)). Checkly формулирует итог так: проблема «was real in 2025», а сейчас «there's no big difference» ([Checkly](https://www.checklyhq.com/blog/mcp-vs-cli-token-efficiency/)). Единственное сопоставимое сравнение надёжности провела Browser Use, сама конкурирующий вендор. На 100 задачах с одним агентом получилось 60,0 у Playwright MCP, 61,0 у Chrome DevTools MCP и 56,3 у agent-browser. agent-browser потратил меньше всего токенов, но работал медленнее остальных, а все доверительные интервалы включают ноль ([browser-use.com](https://browser-use.com/posts/best-mcp-servers-for-browser-automation)).

Поэтому выбирайте по возможностям, а не по токенам. Chrome DevTools MCP нужен для трасс производительности, Lighthouse и heap-снимков. Учтите, что `lighthouse_audit` производительность пропускает, Core Web Vitals снимаются через `performance_start_trace`, а трассы отправляют URL в CrUX, если не указать `--no-performance-crux` ([savvy.co.il](https://savvy.co.il/en/blog/wordpress-speed/chrome-devtools-mcp-lighthouse-audits/)). Playwright подходит для кроссбраузерности (Firefox, WebKit). `playwright-cli` удобен для нескольких параллельных сессий Claude Code: пользователи HN предпочитают его и жалуются, что Chrome DevTools MCP «really clutters your context», а Playwright MCP с постоянным профилем работает только в одном экземпляре ([HN 47500807](https://news.ycombinator.com/item?id=47500807); [HN 47546241](https://news.ycombinator.com/item?id=47546241)). Если всё же берёте MCP, у Microsoft есть флаги экономии: `--snapshot-mode none`, `--image-responses omit`, `--mobile` и `--isolated` для параллельной работы ([Playwright MCP README](https://github.com/microsoft/playwright-mcp/blob/main/README.md)). Claude in Chrome в отзывах называют медленным: ему нужно больше циклов, и с 5–6 сложными вкладками он теряет контекст ([HN 46339777](https://news.ycombinator.com/item?id=46339777); [aitoolanalysis](https://aitoolanalysis.com/claude-in-chrome-review/)).

### Figma ломается на тарифах, а Penpot — открытая альтернатива

Независимого замера точности Figma MCP нет, а цифры вроде «85–95 % для компонентных фреймов» в гайдах ничем не подкреплены. Реальные отзывы сходятся: цвета, шрифты и структура обычно верны, ошибки бывают в картинках, иконках, отступах и адаптивности ([freeCodeCamp](https://www.freecodecamp.org/news/figma-mcp-vs-kombai-frontend-clone-comparison/); [dev.to/oikon](https://dev.to/oikon/can-ai-tools-implement-designs-perfectly-h36)). Главные жалобы 2026 года не про модель, а про тарифы. На Starter доступно 6 вызовов в месяц независимо от места, а лимиты зависят от плана **команды, которой принадлежит файл**. Пользователь с местом Dev на плане Education всё равно упирался в лимиты Starter; обходной путь — дублировать файл в свою команду ([forum 58391](https://forum.figma.com/report-a-problem-6/i-m-having-an-issue-with-figma-mcp-and-i-d-really-appreciate-your-help-58391); [forum 53825](https://forum.figma.com/share-your-feedback-26/mcp-limits-should-be-cross-team-53825)). Ещё жалуются, что запись на холст падает с «Couldn't send to Figma», а генерация медленная и тратит много токенов ([forum 52135](https://forum.figma.com/report-a-problem-6/remote-mcp-generate-figma-design-in-claude-code-always-fails-with-couldn-t-send-to-figma-52135); [forum 53779](https://forum.figma.com/report-a-problem-6/figma-mcp-53779)). Есть и неочевидная ловушка: каталог коннекторов Anthropic предупреждает, что `get_screenshot` в Claude и Claude Code «is currently limited to returning a descripton of screenshots» ([claude.com](https://claude.com/marketplace/connectors/figma)). Эталонный PNG для попиксельного сравнения лучше экспортировать из Figma в `design/` вручную. Плагин Figma стоит ~2,4 тыс. постоянных токенов [лаб.]. На Starter практичнее community Framelink с персональным токеном ([Framelink](https://github.com/GLips/Figma-Context-MCP/blob/main/README.md)).

Для открытых и self-hosted команд лучший вариант — официальный Penpot MCP, теперь внутри основного репозитория (`penpot/penpot`, папка `mcp/`; отдельный `penpot-mcp` заархивирован 3 февраля 2026). Локально он запускается командой `npx -y @penpot/mcp@latest`. В Penpot нужно загрузить плагин `http://localhost:4400/manifest.json` и нажать «Connect to MCP server», а подключение к Claude Code делается командой `claude mcp add penpot -t http http://localhost:4401/mcp` [README]. Вкладку с плагином нельзя закрывать, а в Chromium 142+ ей нужно разрешить доступ к `localhost`. Агент исполняет произвольный код в окружении плагина, поэтому работайте на копии файла ([penpot/penpot mcp](https://github.com/penpot/penpot/tree/develop/mcp); [docs/mcp](https://github.com/penpot/penpot/blob/develop/docs/mcp/index.md)). Остальные дизайн-инструменты нишевые. Canva и Adobe for creativity есть в официальном маркетплейсе, но рассчитаны на маркетинговую графику. Anima стала Agent Grid (`claude mcp add --transport http anima https://api.agentgrid.io/v1/mcp`) [README]. Locofy требует `mcp.json` на каждый проект. README Webflow даёт только SSE-адрес ([AnimaApp/mcp-server-guide](https://github.com/AnimaApp/mcp-server-guide); [@locofy/mcp](https://www.npmjs.com/package/@locofy/mcp); [webflow/mcp-server](https://github.com/webflow/mcp-server)). Для ассетов: иконки и иллюстрации в векторе — Recraft remote MCP, фото-героев — `shinpr/mcp-image` (Gemini, GPT Image, Seedream: `claude mcp add mcp-image --env GEMINI_API_KEY=your-api-key --env IMAGE_OUTPUT_DIR=/absolute/path/to/images -- npx -y mcp-image`) [README]; ([mcp-image](https://github.com/shinpr/mcp-image)). Каждый вызов платный, поэтому заранее говорите Claude, сколько вариантов делать.

### Анимация, доступность и визуальная регрессия обходятся без платных сервисов

Для анимации в React и Vue появился официальный **Motion AI Kit**. `npx motion-ai` ставит скил и настраивает бесплатный хостинговый MCP `https://mcp.motion.dev` без ключа, а в пакете есть ещё субагент `motion-reviewer`; аудиты MotionScore доступны только в платном Motion+ ([motiondivision/ai-kit](https://github.com/motiondivision/ai-kit)). Его правила конкретны: анимировать transform, opacity, clipPath и filter, при смене раскладки использовать `layout`, держать UI-анимации в пределах 150–300 мс для мелких элементов и не ставить overshoot на «serious website like stock trading» ([motion-ai](https://www.npmjs.com/package/motion-ai)). Проверьте, что именно `npx motion-ai` записал в `.claude/` и в конфиг MCP. Для маркетинговых страниц, ScrollTrigger и SVG по-прежнему подходят официальные `gsap-skills`. Оба набора ставить имеет смысл, только если в проекте есть обе библиотеки: их советы о выборе между CSS и библиотекой расходятся.

Визуальную регрессию надёжнее всего делать встроенным в Playwright `toHaveScreenshot()`: Claude сам пишет тесты и запускает `npx playwright test`, никакой MCP не нужен. Допуски задаются через `maxDiffPixels` и `threshold`. Но рендер зависит от «host OS, version, settings, hardware… headless mode», поэтому эталоны снимайте в том же Docker или CI, где идут тесты ([Playwright docs](https://github.com/microsoft/playwright/blob/main/docs/src/test-snapshots-js.md)). Иначе Claude начнёт «чинить» различия, которые на самом деле вызваны разницей в рендеринге шрифтов. И никогда не позволяйте агенту запускать `--update-snapshots` без просмотра diff человеком: готовое правило `ask` есть в разделе о разрешениях. Бесплатный стек доступности такой: ревью `web-design-guidelines`, затем `lighthouse_audit` из Chrome DevTools MCP. Платные варианты есть, но с оговорками. Официальный axe MCP от Deque требует Docker и подписку Axe DevTools ([dequelabs](https://github.com/dequelabs/axe-mcp-server-public)). BrowserStack MCP (`https://mcp.browserstack.com/mcp`) умеет сканировать localhost, а Percy в нём работает только с лицензией ([browserstack/mcp-server](https://github.com/browserstack/mcp-server)). Applitools MCP настраивает проекты только через Playwright Fixtures SDK ([applitools/mcp](https://github.com/applitools/mcp)). Lighthouse CI годится как гейт в CI, хотя его `@lhci/cli` последний раз выходил в июне 2025 года ([lighthouse-ci](https://github.com/GoogleChrome/lighthouse-ci)).

## SVG и 2D: Claude пишет валидный код, но видит результат только через растр

### Модели сильны в синтаксисе и слабы в геометрии, а max effort может не вернуть ничего

Самая полезная для практики находка о качестве SVG касается не модели, а уровня effort. 22 сентября 2026 года Simon Willison попросил Opus 5.5 на уровне `max` нарисовать пеликана на велосипеде, и модель впервые за историю теста «failed to return a response». Она упёрлась в **лимит 128 000 выходных токенов**, так и не закончив рассуждать, и повторная попытка закончилась так же ([simonwillison.net](https://simonwillison.net/2026/Sep/22/opus-and-sol-and-luna/)). У Sonnet 5.5 на `max` та же ошибка, а Haiku 5.5 на `max` работал 5 минут 9 секунд и выдал годный SVG ([тег pelican](https://simonwillison.net/tags/pelican-riding-a-bicycle/); [Haiku 5.5](https://simonwillison.net/2026/Oct/7/claude-haiku-5-5/)). У Opus 4.8 правильная рама велосипеда получилась только на `max` ([Opus 4.8](https://simonwillison.net/2026/May/28/claude-opus-4-8/)). Opus 4.7 уступил локальной Qwen3.6-35B-A3B ([Qwen beats Opus](https://simonwillison.net/2026/apr/16/qwen-beats-opus)). Сам автор называет тест «probably the world's stupidest benchmark» ([2026 in LLMs](https://simonwillison.net/2026/Sep/27/2026-in-llms-so-far/)). Вывод для Claude Code практичный: для SVG ставьте `high` или `xhigh`, но не `max`, и держите каждый файл небольшим.

Структурированные бенчмарки дают более ровную картину. В SVGBench (100+ промптов, оценка по требованиям) первое место у **claude-opus-4.6 (medium) с 75,6 %**, у gpt-5.2 (xhigh) 74,4 %. Режим thinking не помог Opus 4.5: 72,0 % без него против 71,5 % с ним. Записей для Opus 4.7+ и 5.x пока нет ([SVGBench](https://github.com/johnbean393/SVGBench)). Graphic-Design-Bench показал почти идеальную валидность SVG у Opus 4.6 (0,98–1,00) и лучший SSIM в задачах text-to-stroke и text-to-container. А вот по картинке-образцу модель отстаёт от GPT-5.4: image-to-chart 0,731 против 0,833 ([arXiv 2604.04192](https://arxiv.org/pdf/2604.04192)). Сильная сторона Claude — валидный код и следование инструкциям, слабая — пространственная правильность и совпадение с образцом. Именно это и исправляет цикл с рендером. Пользователи добавляют два правила. Правки должны быть конкретными («move a circle 10 units left and thicken the stroke»), а не расплывчатыми («make it pop more») ([dev.to](https://dev.to/tariqhassan/can-claude-generate-images-what-actually-works-in-2026-2mlg)). Большие диаграммы стоит строить частями, потому что целиком они не помещаются в лимит одного ответа ([excalidraw-diagram-skill](https://github.com/coleam00/excalidraw-diagram-skill/blob/main/SKILL.md)). Для логотипов делайте несколько направлений и сравнивайте их в размере иконки приложения ([neonwatty](https://neonwatty.com/posts/logo-designer-skill-claude-code/)). У `logo-design-skill` (создан 26 сентября 2026 года) независимых отзывов пока нет.

### Проверенный конвейер: растр, SVGO без inlineStyles и контроль ссылок доступности

Конфиг SVGO из первого отчёта проверили на двух файлах. Первый — `logo.svg` с `viewBox`, `role="img" aria-labelledby="logo-title logo-desc"`, `<title id>`, `<desc id>` и встроенным `<style>`, где анимированы `#pulse-dot` и `#spinner` и есть блок `@media (prefers-reduced-motion: reduce)`. Второй — тот же файл без `<style>`, с id под внешний GSAP. Пресет по умолчанию сжал первый файл на 28,8 %, но **удалил id `spinner` и `pulse-dot`**: перенёс их правила в `style="animation:spin 4s linear infinite;…"` и выбросил блок reduced-motion. Конфиг первого отчёта (−28,3 %) дал ровно ту же потерю. Причина в коде плагина `inlineStyles`: строка `delete selectedEl.attributes.id;`, а `cleanupIds` при наличии `<style>` и так ничего не трогает. Поэтому отключение `cleanupIds` не помогает ([inlineStyles.js](https://github.com/svg/svgo/blob/main/plugins/inlineStyles.js); [cleanupIds.js](https://github.com/svg/svgo/blob/main/plugins/cleanupIds.js)). Во втором файле пресет по умолчанию (−38,2 %) оставил только `id="a"` и снял id с `<title>` и `<desc>`, а `aria-labelledby` остался — ссылка повисла в пустоте. Конфиг первого отчёта на этом файле работает: сохранил все id, кроме нулевого по размеру элемента. Конфиг с добавленным `inlineStyles: false` сжал первый файл на 23,4 % и сохранил все 8 значимых id, правило reduced-motion, `<title>` и `viewBox`. Файл `svgo.config.mjs` в текущем каталоге SVGO подхватывает сам [лаб.].

Рендереры для самопроверки тоже проверили. Rust-бинарник resvg 0.48.1 скачивается напрямую с `https://github.com/linebender/resvg/releases/latest/download/resvg-linux-x86_64.tar.gz` (архив 1,9 МБ). На анимированном файле он печатает `The @keyframes rule is not supported. Skipped.` и `The @media rule is not supported. Skipped.` ([resvg](https://github.com/linebender/resvg)). Эти предупреждения — дешёвый автоматический сигнал, что файл анимирован и статического рендера мало. Если в сборке ffmpeg есть `--enable-librsvg`, она тоже растеризует SVG. ImageMagick 6.9 сам SVG не рендерит: команда `convert` упала с «delegate failed `'rsvg-convert'…`». Все рабочие рендереры (resvg-js, Rust resvg, ffmpeg с librsvg) дали одинаковый статический кадр, а без `-w` выводили заявленные в файле 128×128 [лаб.].

```js
// svgo.config.mjs — для SVG с анимацией и доступностью   [лаб.: проверено на SVGO 4.1.0]
export default {
  multipass: true,
  plugins: [
    { name: 'preset-default', params: { overrides: {
      inlineStyles: false,      // иначе правила #id из <style> уходят в style="", id удаляются, @media reduced-motion пропадает
      cleanupIds: false,        // сохраняет id для внешнего CSS/GSAP и для <title id>/<desc id>
      collapseGroups: false, convertShapeToPath: false, mergePaths: false,   // структура, на которую ссылается анимация (вывод первого раунда)
    } } },
  ],
};
```

```bash
resvg logo.svg logo.png -w 512                     # [лаб.] Rust resvg 0.48.1; предупреждение про @keyframes = файл анимирован
ffmpeg -width 512 -i logo.svg logo_ffmpeg.png      # [лаб.] запасной путь через librsvg, если ffmpeg собран с --enable-librsvg
npx svgo logo.svg -o logo.min.svg                  # [лаб.] svgo.config.mjs из текущего каталога подхватывается сам
# После SVGO: все цели aria-labelledby должны существовать   [выведено]
grep -o 'aria-labelledby="[^"]*"' logo.min.svg | cut -d'"' -f2 | tr ' ' '\n' | \
  while read -r id; do grep -q "id=\"$id\"" logo.min.svg || echo "нет id: $id"; done
```

### Анимированный SVG проверяют в настоящем браузере по кадрам

resvg рисует только статику, поэтому анимацию нужно останавливать и снимать в браузере. Проверка подтвердила рабочий приём. В Chromium через Playwright `document.getAnimations()` вернул обе CSS-анимации логотипа. После паузы и `currentTime = 750` кадр показал увеличенную точку и повёрнутый квадрат. В контексте с `reducedMotion: 'reduce'` анимаций стало ноль, то есть исходный медиазапрос работает [лаб.]. Этот же тест ловит поломку от неправильного SVGO: после пресета по умолчанию reduced-motion перестаёт действовать. Для SMIL то же самое делают `svg.pauseAnimations()` и `svg.setCurrentTime(t)` ([MDN pauseAnimations](https://developer.mozilla.org/en-US/docs/Web/API/SVGSVGElement/pauseAnimations); [MDN setCurrentTime](https://developer.mozilla.org/en-US/docs/Web/API/SVGSVGElement/setCurrentTime)). Анимацию на таймерах и `requestAnimationFrame`, например GSAP, двигает часами `page.clock` из Playwright или `timeline.pause().seek(t)` ([Playwright clock](https://github.com/microsoft/playwright/blob/main/docs/src/clock.md)). Кадры удобно склеить в один лист и показать Claude одну картинку вместо пяти. Скил Figma советует вообще предпочитать CSS/JS вместо SMIL, а анимированный SVG через Figma MCP получить нельзя ([unsupported-and-fallbacks.md](https://github.com/figma/mcp-server-guide/blob/main/skills/figma-implement-motion/references/unsupported-and-fallbacks.md)).

```js
// sample-svg.mjs — кадры CSS-анимации и проверка reduced-motion   [выведено по сценарию проверки]
// node sample-svg.mjs logo.svg 0 750 1500
import { chromium } from 'playwright';
import { pathToFileURL } from 'node:url';
const [file, ...times] = process.argv.slice(2);
const browser = await chromium.launch();
for (const reducedMotion of ['no-preference', 'reduce']) {
  const page = await browser.newPage({ reducedMotion });
  await page.goto(pathToFileURL(file).href);
  console.log(reducedMotion, 'animations:', await page.evaluate(() => document.getAnimations().length));
  for (const ms of times) {
    await page.evaluate(t => document.getAnimations().forEach(a => { a.pause(); a.currentTime = t; }), Number(ms));
    await page.screenshot({ path: `frame_${reducedMotion}_${ms}.png` });
  }
}
await browser.close();
```

### Диаграммы, графики и шрифты: выбирайте инструменты, которые пишут файл

Не каждый официальный коннектор работает в Claude Code, и это видно по полю `worksWith` в каталоге Anthropic. Adobe, Miro и Whimsical, а также Canva, Figma, Lucid и Cloudinary перечисляют `claude-code`. tldraw его не перечисляет, Mermaid Chart указан только для claude.ai, а Affinity — только для Claude Desktop ([каталог коннекторов](https://claude.com/marketplace/connectors-plugins)). Заодно разрешилась путаница с адресом Mermaid Chart: в каталоге указан `https://chatgpt.mermaid.ai/anthropic/mcp`. Этот сервер — виджет MCP App, как и tldraw, чей `exec` ждёт, пока страница виджета подхватит запрос, так что в терминале он, скорее всего, повиснет ([Mermaid Chart](https://claude.com/marketplace/connectors/mermaid-chart); [tldraw mcp-app](https://github.com/tldraw/tldraw/blob/main/apps/mcp-app/README.md)). Для репозитория нужны инструменты, которые выдают файл: `mmdc`, `d2`, draw.io, Kroki по HTTP. Miro (официальный плагин v2.0.0, 31 инструмент, `diagram_create`, `diagram_get_dsl`) хорош для совместных досок, но SVG не отдаёт. Lucid экспортирует только PNG ([Miro plugin](https://github.com/miroapp/miro-ai/tree/main/claude-plugins/miro); [Lucid](https://claude.com/marketplace/connectors/lucid)). `generate_diagram` из Figma превращает Mermaid в редактируемую диаграмму FigJam, но отвергает эмодзи и молча выбрасывает `Note over X` ([figma-generate-diagram](https://github.com/figma/mcp-server-guide/blob/main/skills/figma-generate-diagram/SKILL.md)).

Для графиков в SVG лучший путь вообще без MCP: Claude пишет спецификацию Vega-Lite, а `vl-convert vl2svg` рендерит её офлайн. Внутри у него встроенные Vega и Vega-Lite, локальные файлы по умолчанию заблокированы ([vl-convert](https://github.com/vega/vl-convert)). Популярный `antvis/mcp-server-chart` (4,4 тыс.★) возвращает не SVG, а URL картинки. Причём по умолчанию данные уходят на `https://antv-studio.alipay.com/api/gpt-vis` ([mcp-server-chart](https://github.com/antvis/mcp-server-chart)). Для логотипов текст на финале переводят в кривые. Проверка показала: `python -I -m fontTools.pens.svgPathPen LiberationSans-Bold.ttf "Logo"` (fonttools 4.67.0) выдаёт только `<path>` без `<text>`, в единицах шрифта с переворотом по Y и **без `viewBox`**, который придётся вычислить самостоятельно [лаб.]. Кроме того, этот CLI раскладывает глифы по одному, без OpenType-шейпинга: для кернинга подходит opentype.js `Font.getPath(text, x, y, fontSize, {kerning})`, для арабского и индийских письменностей нужен HarfBuzz ([svgPathPen.py](https://github.com/fonttools/fonttools/blob/main/Lib/fontTools/pens/svgPathPen.py); [opentype.js](https://github.com/opentypejs/opentype.js)). Если установлен Inkscape, проще всего `--export-text-to-path` ([man inkscape](https://gitlab.com/inkscape/inkscape/-/blob/master/man/inkscape.pod.in)). Лицензированные шрифты подбирают инструменты Adobe Fonts в коннекторе Adobe (`font_search`, `font_recommend`, `font_preview`). MCP для Google Fonts пока незрелые, у всех от 0 до 9★. После перевода в кривые сохраните `<title>` и `aria-label`.

### Remotion получил официальный плагин, а его MCP формально ещё жив

У Remotion теперь есть официальный плагин для Claude Code. Ставится он двумя командами `claude plugin marketplace add remotion-dev/claude-code-plugin` и `claude plugin install remotion@remotion`, после чего Claude Code нужно перезапустить. Пример вызова: `/remotion:remotion-create Make a promo video for a record store`. Манифест плагина имеет ту же версию, что и сам Remotion (4.0.536), и содержит те же 12 скилов ([claude-code-plugin.mdx](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/ai/claude-code-plugin.mdx); [plugin.json](https://github.com/remotion-dev/claude-code-plugin/blob/main/.claude-plugin/plugin.json)). Плагин удобнее `npx skills`: ставится и обновляется одной командой, его версия совпадает с версией Remotion, а при `--scope project` в репозиторий попадает только запись в `.claude/settings.json`. Судьба Remotion MCP так и не прояснилась. Документация по-прежнему пишет «shut down no earlier than August 31, 2026». Тикет #9055 закрыт 16 июля без единой даты. А клиент `@remotion/mcp` 4.0.536 вышел 16 октября 2026 года и в октябре получал исправления ([mcp.mdx](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/ai/mcp.mdx); [issue #9055](https://github.com/remotion-dev/remotion/issues/9055); [npm](https://www.npmjs.com/package/@remotion/mcp)). Агентную интеграцию Remotion переносит в Studio WebMCP: в августе и сентябре там появились инструменты `get_current_error` и управление жизненным циклом Studio ([commit a79dba5c](https://github.com/remotion-dev/remotion/commit/a79dba5c)). Практический вывод: MCP считать «устаревшим, но, возможно, ещё отвечающим» и ничего нового на нём не строить.

Отзывы о Remotion сходятся: скилы ускоряют написание кода анимации, но монтажёра не заменяют. В тесте Wireflow (вендор, продаёт свой видеопродукт) один промпт дал 12-секундный ролик 1080p примерно за 9 минут, 22 хода и около $1 по прейскуранту API ([wireflow.ai](https://www.wireflow.ai/blog/claude-motion-graphics)). Обзор Quickleap: «It's replacing the part where you manually write animation code», а без опыта Remotion «the barrier is still high» ([quickleap.io](https://quickleap.io/blog/remotion-claude-code-skill-review)). В комментариях к YouTube-обзору разработчик получил похожий результат вовсе без скилов, а другой назвал их просто сборником best practices ([YouTube](https://www.youtube.com/watch?v=7OR-L0AySn8)). У новичков типичные огрехи — смещённый центр, тесная плашка выделения, съехавший текст, и они исправляются обычными уточнениями ([Medium](https://medium.com/@ai-with-eric/claude-code-remotion-professional-content-with-zero-video-skills-3545498407ff)). Отсюда совет Tella: «treat a first prompt as a brief, not a magic render button» ([tella.com](https://www.tella.com/blog/how-to-use-remotion-agent-skills-with-claude-code)). Расходы на рендер в Lambda предсказуемы. По собственным примерам Remotion шаблон HelloWorld стоит $0,001, минутный ролик из того же бакета — $0,017, а десятиминутное HD-видео с удалённым источником — $0,103 за 56 секунд. При этом «Rendering a video inside your video increases the cost significantly», а уменьшение памяти линейно снижает цену ([cost-example.mdx](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/lambda/cost-example.mdx); [cost.mdx](https://github.com/remotion-dev/remotion/blob/main/packages/docs/docs/lambda/cost.mdx)). Компаниям больше трёх сотрудников по-прежнему нужна Company License ([LICENSE.md](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)).

### HyperFrames быстро стартует, но молча выдаёт битые рендеры

HyperFrames хвалят за удобство для агентов и бесплатную лицензию Apache-2.0. Kompozy поставил ему 3,8/5 («an excellent free primitive»), но отметил, что он рендерит один клип и останавливается: без сценария, аватара и публикации. Сам Kompozy продвигает свой продукт ([kompozy.io](https://kompozy.io/reviews/heygen-hyperframes)). Apito прошёл с Claude Code весь цикл до вертикального MP4 1080×1920 ([apito.ai](https://apito.ai/en/blog/dev-guides/claude-code-hyperframes-video-generation/)). Это самый тяжёлый плагин в контексте: **~3 945 постоянных токенов**, а `talking-head-recut` при вызове занимает 22,6 тыс. [лаб.]. Главный риск — в трекере ошибок за август–октябрь 2026 года. В #3352 пример рендерит 2 уникальных кадра, а `check` и `render` оба сообщают об успехе. В #5551 MP4 теряет правые 8 px, если ширина не кратна 16 (с версии 0.8.81). В #4899 Docker-рендер сдвигает цвета из-за тега BT.601 вместо BT.709. В #5492 растёт память на длинных рендерах. В открытом #5473 `render --docker` зависает около 200-го кадра при двух одновременных видеоклипах ([#3352](https://github.com/heygen-com/hyperframes/issues/3352); [#5551](https://github.com/heygen-com/hyperframes/issues/5551); [#4899](https://github.com/heygen-com/hyperframes/issues/4899); [#5492](https://github.com/heygen-com/hyperframes/issues/5492); [#5473](https://github.com/heygen-com/hyperframes/issues/5473)). Правила работы отсюда простые: закрепляйте версию, ширину берите кратной 16 и проверяйте кадры, а не код возврата CLI.

Производительность HyperFrames настраивается встроенными средствами. `npx hyperframes benchmark` прогоняет конфигурации по fps, качеству и числу воркеров. Каждый воркер — отдельный Chrome примерно на 256 МБ. Режим экономии памяти включается сам при 8 ГБ RAM и меньше, но смотрит на память хоста, а не на лимиты cgroup. Поэтому в Docker задавайте `PRODUCER_LOW_MEMORY_MODE` явно ([cli.mdx](https://github.com/heygen-com/hyperframes/blob/main/docs/packages/cli.mdx)). В Lambda по умолчанию выделяется 10 240 МБ. Пример на 480 кадров и 5 функций стоил $0,0214, распределённый рендер поддерживает только SDR, а каждый фрагмент должен уложиться в 15 минут ([aws-lambda.mdx](https://github.com/heygen-com/hyperframes/blob/main/docs/deploy/aws-lambda.mdx)). Ставить можно из официального маркетплейса [лаб.] или из собственного маркетплейса HeyGen; во втором случае после установки нужен `git lfs pull`. Сравнения «HyperFrames против Remotion» почти все написаны вендорами. Общая мысль у них такая: HTML агентам писать проще, а Remotion зрелее, у него больше сообщество и проверенный масштаб в Lambda ([voyager.so](https://voyager.so/blog/hyperframes-vs-remotion); [HeyGen](https://hyperframes.heygen.com/guides/hyperframes-vs-remotion)).

### Монтаж: транскрипт вместо просмотра, файлы NLE вместо живого управления

Для монтажа главный принцип прежний: Claude читает транскрипт, а не смотрит видео. video-use с апреля по начало июля 2026 года собрал больше 13 тыс. звёзд. Он предлагает стратегию, ждёт одобрения и опирается на пословный транскрипт ElevenLabs и PNG-ленты кадров и волны ([dev.to](https://dev.to/andrew-ooo/video-use-review-browser-use-teams-ai-video-editor-58nl)). Независимой оценки качества его склеек нет, а пользователи уже спрашивают, что уходит в ElevenLabs при транскрипции ([issue #18](https://github.com/browser-use/video-use/issues/18)). Его «Hard Rules» стоит перенести в свой CLAUDE.md: субтитры последним шагом, склейка через `-c copy`, аудиофейды по 30 мс на стыках, никогда не резать внутри слова, запас 30–200 мс ([SKILL.md](https://github.com/browser-use/video-use/blob/main/SKILL.md)). Для auto-editor отзывов именно с Claude не нашлось. Практики советуют начинать с 1–3-минутного фрагмента: сначала паузы, потом субтитры, потом оформление ([st-hakky](https://book.st-hakky.com/en/docs/claude-code-video-editing-automation)).

**Первый отчёт нужно поправить в части монтажных программ.** 8 сентября 2026 года DaVinci Resolve 21.1 получил официальный встроенный MCP для Claude, Claude Code и ChatGPT Codex. Включается он через File > Setup AI Assistants и работает только в Studio, потому что Python-скриптинг в этом релизе стал платным ([digitalproduction.com](https://digitalproduction.com/2026/09/08/resolve-21-1-adds-mcp-and-finally-gets-presets/); [ymcinema](https://ymcinema.com/2026/09/17/davinci-resolve-21-1-mcp-ai-assistants-control-edit/)). Первый обзор показал ограничения. У ассистента 14 общих инструментов, и в основном он пишет Python против API скриптинга. Цвет он настраивает через LUT, CDL, DRX и включение нод, но «Colour wheels, curves and masks are not exposed». Сгенерированные скрипты получают тот же доступ к диску и сети, поэтому начинать стоит с запросов только на чтение. Studio стоит около €308 ([nordlys.io](https://nordlys.io/en/blog/davinci-resolve-mcp-ai-asistent)). Community-сервер samuelgursky по-прежнему даёт больше инструментов, но проверен в основном на Mac с Claude Desktop ([FEATURES.md](https://glama.ai/mcp/servers/@samuelgursky/davinci-resolve-mcp/blob/19dc53236193de61f79facc731024a75d3c3be5c/docs/FEATURES.md)). Для остальных программ безопаснее всего файловые форматы. Final Cut Pro закрывает `DareDev256/fcp-mcp-server`: 15 сгруппированных инструментов и 102 операции над FCPXML, FCP 10.4+. Версии 0.19.2–0.21.0 на PyPI вышли без `tools/` и падают с «Connection closed». Транзакционный вариант с подтверждением по хешу — `dreliq9/fcp-mcp` ([fcp-mcp-server](https://github.com/DareDev256/fcp-mcp-server); [fcp-mcp](https://github.com/dreliq9/fcp-mcp)). Для Shotcut есть плагин `matrodrigs/shotcut-mcp` с транзакционной записью `.mlt`: `/plugin marketplace add matrodrigs/shotcut-mcp`, затем `/plugin install shotcut-mcp@matrodrigs` [README]. Автор сервера для Kdenlive предупреждает, что файл `.kdenlive` «fails silently — wrong frame rate, missing audio», и сверяет результат по отрендеренным кадрам ([shotcut-mcp](https://github.com/matrodrigs/shotcut-mcp); [kdenlive-editing-mcp](https://github.com/tiagovignatti/kdenlive-editing-mcp)). Для OBS самый полный сервер — `Tom-R-Main/OBS-MCP`, 171 инструмент. Его можно запустить только на чтение (`OBS_MCP_TOOLSETS=core OBS_MCP_READ_ONLY=true`), а с `OBS_MCP_CONFIRM_LIVE=true` остановка эфира требует подтверждения человека. npm-релиза у него пока нет ([OBS-MCP](https://github.com/Tom-R-Main/OBS-MCP)). Облачный Quick Cut из Adobe for creativity работает с файлами в Creative Cloud: длительность для него — «soft target», ссылка на результат истекает, а таймлайном десктопного Premiere он не управляет ([adobe-edit-quick-cut](https://github.com/adobe/skills/blob/main/plugins/creative-cloud/adobe-for-creativity/skills/adobe-edit-quick-cut/SKILL.md)).

### Генерация, озвучка и звук: хостинговые серверы с OAuth и локальные утилиты

Репозиторий локального `elevenlabs-mcp` заархивирован, и проверенный путь теперь — официальный плагин. Он подключает хостинговый `https://api.us.elevenlabs.io/v1/mcp` с заранее зарегистрированным OAuth-клиентом и инструментами `creative_generate_speech`, `creative_generate_video`, `creative_transcribe_audio` и другими ([mcp.json](https://github.com/elevenlabs/plugin/blob/main/mcp.json)). Правила его скила стоит перенести и в собственные промпты: «Pass `estimate_only: true` to price a long video… Never call a generation tool a second time to 'retry'». Заметьте, что по умолчанию `generations_count` = 4, то есть одна просьба превращается в четыре платные генерации ([creative-studio SKILL.md](https://github.com/elevenlabs/plugin/blob/main/skills/mcp/creative-studio/SKILL.md)). Команду `claude mcp add --transport http elevenlabs https://api.elevenlabs.io/v1/mcp` CLI принимает [лаб.: принято], но пройдёт ли с ней OAuth, не проверено. Плагин `runway-api@claude-plugins-official` закреплён на v3.0.0: там прямые скилы генерации `rw-generate-*` и нет MCP. Актуальная v4 ставится командами `claude plugin marketplace add runwayml/skills` и `claude plugin install runway-api@runway-dev`. Она подключает Runway Dev MCP (`https://dev.runwayml.com/mcp`) с входом через браузер; API-ключ в его конфиг класть не нужно ([runwayml/skills](https://github.com/runwayml/skills); [marketplace.json](https://github.com/anthropics/claude-plugins-official/blob/main/.claude-plugin/marketplace.json)). Собственный конфиг плагина Replicate объявляет `"type": "http"` на адресе `/sse`. Поэтому лучше `claude mcp add --transport http replicate https://mcp.replicate.com/sse --scope user` [выведено], а SSE-вариант со страницы Replicate оставьте запасным ([.mcp.json](https://github.com/replicate/skills/blob/main/.mcp.json)). У fal две официальные страницы противоречат друг другу: `/mcp-relay` с OAuth и `/mcp` с заголовком Bearer. Ключ держите в `${FAL_KEY}` ([fal docs](https://fal.ai/docs/documentation/setting-up/mcp)). Аватары даёт HeyGen: `claude mcp add --transport http heygen https://mcp.heygen.com/mcp/v1/` [README]. Режим MCP тратит кредиты плана, CLI тарифицируется отдельно по API, и при заданном `HEYGEN_API_KEY` побеждает CLI ([heygen-com/skills](https://github.com/heygen-com/skills)). Для поиска по видеотеке и вопросов по длинным роликам есть официальный плагин TwelveLabs. Синхронный анализ — до часа видео, асинхронный — до двух, но материал при этом уходит третьей стороне ([TwelveLabs plugin](https://github.com/twelvelabs-io/twelve-labs-claude-code-plugin)).

Звук для видео почти всегда проще делать в Bash, чем через MCP для DAW. Meta заархивировала Demucs, поддерживаемый форк — `adefossez/demucs` v4.1.0, вызов `uvx demucs --two-stems=vocals file.mp3` ([demucs](https://github.com/adefossez/demucs)). `ffmpeg-normalize` 1.43.0 по умолчанию делает два прохода и имеет пресеты `podcast` (−16 LUFS) и `streaming-video` (−14 LUFS) ([presets.md](https://github.com/slhck/ffmpeg-normalize/blob/master/docs/usage/presets.md)). У фильтра `loudnorm` по умолчанию `I=-24`, а в динамическом режиме он повышает частоту до 192 кГц, поэтому добавляйте `-ar` ([filters.texi](https://github.com/FFmpeg/FFmpeg/blob/master/doc/filters.texi)). MCP для DAW оправданы, только если человек продолжит работу в этой программе. Audacity-MCP (144 инструмента) работает лишь с Audacity 3.x, потому что «Audacity 4 removed `mod-script-pipe`» ([Audacity-MCP](https://github.com/xDarkzx/Audacity-MCP)). Для REAPER есть `xDarkzx/Reaper-MCP` на 181 инструмент и новый `creaper`. creaper сам измеряет громкость и спектр («Claude can't hear»), а каждую правку оформляет отдельным шагом отмены ([Reaper-MCP](https://github.com/xDarkzx/Reaper-MCP); [creaper](https://github.com/nickcapron/creaper)). Для локальной озвучки подходит Kokoro-FastAPI с OpenAI-совместимым эндпоинтом: `docker run -p 8880:8880 ghcr.io/remsky/kokoro-fastapi-cpu:latest` ([Kokoro-FastAPI](https://github.com/remsky/Kokoro-FastAPI)). Piper переехал в `OHF-Voice/piper1-gpl` и сменил лицензию на GPL ([piper1-gpl](https://github.com/OHF-Voice/piper1-gpl)). Музыку генерирует скил ElevenLabs с моделью `music_v2_5`. Официального API или MCP у Suno нет ([music SKILL.md](https://github.com/elevenlabs/skills/blob/main/music/SKILL.md)). Для математических роликов достаточно скила и Bash: `npx skills add adithya-s-k/manim_skill` покрывает ManimCE и ManimGL, которые между собой несовместимы. `Yusuke710/manim-skill` даёт полный конвейер в стиле 3Blue1Brown: дикторский текст → Kokoro TTS → код → рендер → сведение → просмотр ([manim_skill](https://github.com/adithya-s-k/manim_skill); [Yusuke710/manim-skill](https://github.com/Yusuke710/manim-skill)).

### Субтитры и исправленные команды проверки видео

Для анимированных субтитров в Remotion и HyperFrames нужны таймкоды по словам, и их даёт WhisperX. На large-v2 он работает в 70 раз быстрее реального времени и укладывается в 8 ГБ видеопамяти. Слова без букв из словаря выравнивающей модели («2014.», «£13.60») он выровнять не может, поэтому числа лучше заранее записать словами ([WhisperX](https://github.com/m-bain/whisperX)). Для пакетной работы на GPU быстрее всего faster-whisper. На 13 минутах аудио с RTX 3070 Ti он с `batch_size=8` уложился в 17 секунд против 2 мин 23 с у openai/whisper. На CPU он вдвое быстрее whisper.cpp: 1 мин 06 с против 2 мин 05 с ([faster-whisper](https://github.com/SYSTRAN/faster-whisper)). Фильтр `whisper` в FFmpeg 8.0 требует сборки с `--enable-whisper`, а в пакете Ubuntu 6.1.1 его нет [лаб.]. Субтитры вшивают через libass: `subtitles=sub.srt:force_style='…'`, а для арабского, иврита, деванагари и тайского обязателен `shaping=complex`. Whisper переводит только на английский. На другие языки Claude сам переводит текст SRT с сохранением таймкодов, после чего нужно заново проверить длину строк ([filters.texi](https://github.com/FFmpeg/FFmpeg/blob/master/doc/filters.texi)).

```bash
# Метаданные: компактный вариант вместо -show_streams                                [лаб.]
ffprobe -v error -show_entries format=duration,size,bit_rate:stream=codec_name,width,height -of json out.mp4
# Кадр в точке склейки                                                               [лаб.]
ffmpeg -ss 4.5 -i out.mp4 -frames:v 1 check_4.5.png
# Контакт-лист из 16 равномерных кадров (исправлено: fps от длительности + один кадр)   [лаб.]
DUR=$(ffprobe -v error -show_entries format=duration -of csv=p=0 out.mp4)             # [выведено]
ffmpeg -i out.mp4 -vf "fps=16/$DUR,scale=320:-1,tile=4x4" -frames:v 1 sheet.png
# Громкость: нужен вывод в null, JSON идёт в stderr                                  [лаб.]
ffmpeg -hide_banner -nostats -i out.mp4 -af loudnorm=print_format=json -f null -
# 16 кГц WAV для whisper.cpp                                                         [лаб.]
ffmpeg -i out.mp4 -ar 16000 -ac 1 -c:a pcm_s16le in.wav
# Экспорт для соцсетей: yuv420p и moov в начале файла                                 [лаб.]
ffmpeg -i out.mp4 -c:v libx264 -pix_fmt yuv420p -movflags +faststart -c:a aac out_social.mp4
# Есть ли whisper-фильтр в этой сборке                                               [лаб.: в Ubuntu 6.1.1 — Unknown filter]
ffmpeg -h filter=whisper
# Стоп-кадры Remotion вместо полного MP4                                             [README]
npx remotion render <composition-id> out/frames --frames=0,30,90 --image-format=png
```

## 3D: агенты уверенно расставляют объекты, но реконструкцию сцены не решает никто

### Бенчмарки показывают, где агенту в Blender можно доверять

В 2026 году появились первые бенчмарки, где агент управляет Blender именно через MCP-интерфейс. В SceneActBench (Tencent Hunyuan и университеты, июль 2026) агент работает с headless Blender: смотрит сцену, пишет Python и рендерит виды для самопроверки. Оценка идёт по скрытой 3D-разметке: 5 задач, 520 случаев ([SceneActBench](https://github.com/Feinaldo2/SceneActBench); [arXiv 2607.22393](https://arxiv.org/pdf/2607.22393)).

| Модель | Раскладка | Камера | Артикуляция | Реконструкция | Динамика | Итог |
|---|---|---|---|---|---|---|
| Doubao Seed 2.0 Pro High | 77,4 | 34,5 | 59,6 | 8,8 | 70,7 | **50,2** |
| **Claude Opus 4.6 High** | 73,5 | 34,0 | 63,7 | 9,8 | 63,2 | **48,9** |
| GPT 5.4 High | 84,1 | 26,4 | 73,8 | 12,3 | 46,7 | 48,7 |
| Gemini 3.1 Pro High | 65,4 | 33,9 | 56,5 | 7,1 | 63,9 | 45,4 |
| Claude Sonnet 5 High | 51,9 | 27,3 | 57,8 | 10,5 | 49,9 | 39,5 |

Сами авторы предупреждают, что итоговые баллы «not evidence that ranks are statistically distinct». Но структура результата однозначна. Раскладка объектов и артикуляция (двери, ящики) дают сильным моделям 56–84 балла, у Opus 4.6 — 73,5 и 63,7. Восстановление сцены по изображениям не решает никто: лучший результат 12,3 из 100. Подбор камеры по референсу держится около 30. 3DHarnessBench (сентябрь 2026) показал, что более богатый доступ к функциям Blender MCP «significantly» улучшает результат у всех фронтир-моделей ([arXiv 2609.06535](https://arxiv.org/pdf/2609.06535)). Ещё в BlenderGym (CVPR 2025) было видно, что вычисления выгоднее делить между генерацией и проверкой ([arXiv 2504.01786](https://arxiv.org/html/2504.01786v1)). Главные сбои в 3DCodeBench — «API mismatches and disconnected or floating geometry» ([arXiv 2606.01057](https://arxiv.org/pdf/2606.01057)). Опыт пользователей это подтверждает. Получаются блокауты, low-poly и процедурные сцены, материалы, свет и пакетный Python. Не получаются органика (к режиму sculpt через MCP доступа нет), продакшн-топология и риг с весами и IK, который «is not realistic» ([MindStudio](https://www.mindstudio.ai/blog/claude-blender-mcp-real-world-performance); [Medium](https://medium.com/@creativeaininja/claude-drives-blender-through-mcp-now-heres-what-actually-changes-684f28f78c7b)). Практика из этого понятная. На каждом шаге давайте агенту рендер. Камеру задавайте числами (позиция, FOV), а не словами «как на фото». Органику берите у генераторов или из библиотек ассетов. Отдельно проверяйте, нет ли висящей геометрии. Для сложных сцен выбирайте модель класса Opus.

### Blender: community-сервер шире, официальный точнее по API

Community-сервер `ahujasid/mcp-for-blender` (бывший blender-mcp) даёт 9 инструментов. Главные — `execute_blender_code`, `get_scene_info` и `look`, которая возвращает лист с несколькими ракурсами. Кроме того, он подключает ассеты Poly Haven и Poly Pizza и генерацию через Tripo, Hunyuan3D, Rodin и Meshy ([README](https://github.com/ahujasid/mcp-for-blender)). README честно описывает странности: первая команда иногда падает, а потом работает, сложные запросы отваливаются по таймауту и их нужно дробить. Один из ранних пользователей насчитал «3+ hours» до первой успешной генерации, но он продаёт конкурирующий продукт ([dev.to](https://dev.to/glglgl/from-blender-mcp-to-3d-agent-the-evolution-of-ai-powered-blender-modeling-1m7d)). Официальный Blender Lab MCP вышел в версии add-on 1.0.3 (нужен Blender 5.1+). Его сервер с версии 1.0.2 закрепляет `mcp<2` и даёт **26 инструментов**: 20 базовых и 6 вариантов `_for_cli` для фонового Blender. Среди них встроенный поиск по API и мануалу (`search_api_docs`, `search_manual_docs`), скриншоты областей и окон и рендер вьюпорта в файл ([зеркало](https://github.com/SJJ-universe/blender-lab-mcp); [StraySpark](https://www.strayspark.studio/blog/official-blender-mcp-server-comparison-2026)). Встроенный справочник бьёт прямо в главный тип сбоя из 3DCodeBench — несовпадения API. Его песочница, по словам самих авторов, «isn't really a sandbox… more of a slap on the wrist». Для Blender 4.x есть только неофициальный форк `blender-mcp-legacy` ([weak_sandbox.py](https://github.com/SJJ-universe/blender-lab-mcp/blob/main/addon/blender_mcp_addon/weak_sandbox.py); [blender-mcp-legacy](https://github.com/jordansoftware/blender-mcp-legacy)). Ставить оба сервера под одним именем `blender` нельзя: у обоих по умолчанию TCP-сокет, поэтому разведите имена и порты. Перед каждой сессией сохраняйте `.blend`, а для community-сервера включайте `BLENDER_MCP_SAFE_MODE=1` (блокирует файловый ввод-вывод, процессы и сеть, но оставляет моделирование и рендер) ([README](https://github.com/ahujasid/mcp-for-blender#limitations--security-considerations)).

```bash
claude mcp add blender uvx mcp-for-blender                 # [лаб.: принято] community, 9 инструментов
uvx mcp-for-blender install-addon                          # [README] затем в Blender: N → Start MCP Server
# Официальный Blender Lab MCP (Blender 5.1+); сервер: pip install git+https://projects.blender.org/lab/blender_mcp.git#subdirectory=mcp
claude mcp add blender-lab -- uvx --from "git+https://projects.blender.org/lab/blender_mcp.git#subdirectory=mcp" blender-mcp   # [выведено]
# Если projects.blender.org закрыт прокси (облачные сессии): клон зеркала и .mcp.json с
#   "command": "uv", "args": ["--directory", "/abs/path/mcp", "run", "blender-mcp"]   [README первого раунда]
```

### Движки: официальные MCP появились, но community пока стабильнее

В **Unity** пользователи по-прежнему выбирают CoplayDev MCP for Unity: он «without unnecessary configuration», и с Claude Code на нём лучше получались editor-скрипты ([Unity Discussions](https://discussions.unity.com/t/cli-mcp-ai-ide-chatgpt-codex-cursor-antigravity-claude-code-windsurf-next-steps-for-unity-workflow-automation/1705679)). Ранние проблемы с переподключением Claude Code, например «no session» после реконнекта в #643, закрыты ([#643](https://github.com/CoplayDev/unity-mcp/issues/643)). Официальный Unity MCP теперь подключается через relay-бинарник, который редактор кладёт в `~/.unity/relay/`. Первое подключение нужно принять в Edit > Project Settings > AI > Unity MCP ([Unity docs](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-get-started.html)). Известные баги: на macOS «no stable connected client is registered in Unity», а при двух открытых редакторах соединение случайно переключается между ними ([issuetracker 9369](https://issuetracker.unity.com/issues/9369/relay-error-no-stable-connected-client-is-registered-in-unity-is-thrown-when-configuring-an-external-mcp-client); [issuetracker 11122](https://issuetracker.unity.com/issues/11122/unity-ai-mcp-connection-resets-when-multiple-unity-instances-are-opened)). Один автор ушёл с официального пакета, потому что relay-процесс «stayed alive after the Editor closed». Он же предупреждает, что при смене сервера придётся переписать ссылки на имена инструментов в настройках Claude Code ([note.com](https://note.com/kludgelog/n/nbd48152e59ab?hl=en)). В **Unreal Engine 5.8** конфигурацию вручную писать не нужно: консольная команда `ModelContextProtocol.GenerateClientConfig ClaudeCode` сама создаёт `.mcp.json` в корне проекта, и Claude Code нужно запускать оттуда ([Epic docs](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor)). Для UE 5.0–5.7 остаётся ChiR24/Unreal_mcp. В **Godot** главная проблема не в инструменте, а в долгом контексте. Девлог фиксирует, что к третьему дню Claude «lost track of earlier decisions» ([itch.io](https://russperry.itch.io/the-mormon-trail-rpg/devlog/1133249/dec-26-devlog)). Другой автор видел зелёные тесты при неиграбельной игре: «Claude can verify correctness but not fun, feel, or visual fidelity». Он же называет Godot с headless-запуском и читаемыми `.tscn` и `.gd` лучшей парой для Claude Code ([Medium](https://chierhu.medium.com/claude-code-for-game-development-7a88fcd19992)). Правила игры держите в рукописном файле как неизменную опору ([dev.to](https://dev.to/datadeer/part-1-building-an-rts-in-godot-what-if-claude-writes-all-code-49f9)).

Новые официальные варианты появились у трёх платформ. В **Roblox Studio** встроен MCP: Assistant Settings → MCP Servers → Quick connect → включить Claude Code. Старый Rust-сервер Roblox заархивировал ([Roblox docs](https://create.roblox.com/docs/studio/mcp); [studio-rust-mcp-server](https://github.com/Roblox/studio-rust-mcp-server)). Поверх встроенного полезен форк `Chrrxs/robloxstudio-mcp`: Luau в живом рантайме, мультиплеерные плейтесты и профайлер ([Chrrxs](https://github.com/Chrrxs/robloxstudio-mcp)). **PlayCanvas** выпустил `@playcanvas/editor-mcp-server`: 130 инструментов, запуск приложения, скриншоты рантайма и VCS-чекпоинты для отката. Требования: Node 22.18+, кнопка MCP под Publish и разрешение Chrome «Apps on device». Сервер добавляйте один раз на агента, потому что «two servers take turns owning the Editor port» ([editor-mcp-server](https://github.com/playcanvas/editor-mcp-server)). Пакет Babylon.js `@babylonjs/mcp-servers` управляет только графовыми редакторами (Node Material, Node Geometry, GUI и другие), а не сценой. Его сессия закрывается после 15 минут простоя ([npm](https://www.npmjs.com/package/@babylonjs/mcp-servers)).

### Веб-3D: headless-скриншот WebGL работает, WebGPU пока нет

Проверку three.js в браузере без GPU провели на практике. Минимальная сцена three.js r186 (`WebGLRenderer` с `preserveDrawingBuffer: true`, куб с `MeshStandardMaterial` и тор-узел) выставляла `window.__frameReady = true` после первого `renderer.render`. Затем Playwright снимал `canvas.screenshot()`. Сцена отрендерилась правильно во **всех шести комбинациях**: headless-shell и new-headless, умноженные на флаги по умолчанию, `--disable-gpu` и явные флаги SwiftShader. Везде WebGL2 шёл через «ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device…))», центральный пиксель был оранжевым `[169,65,31,255]`, а скриншоты совпали попиксельно [лаб.]. **Утверждение первого отчёта, что `--disable-gpu` ломает WebGL в Chrome 130+, здесь не воспроизвелось.** Оговорка: возможно, оно верно на машинах с GPU, которых в проверке не было. Важнее другое. Без явных флагов Chromium пишет «Automatic fallback to software WebGL has been deprecated. Please use the --enable-unsafe-swiftshader…», то есть автоматический откат в будущих версиях могут убрать. WebGPU в headless недоступен: `navigator.gpu` есть, но `requestAdapter()` возвращает null во всех режимах. Поэтому сцены на `WebGPURenderer` проверяйте через WebGL-откат [лаб.]; ([agent-browser](https://agent-browser.dev/webgpu)).

```js
// shot-3d.mjs — headless-проверка WebGL-сцены   [выведено по сценарию проверки; флаги — лаб.]
import { chromium } from 'playwright';
const browser = await chromium.launch({ args: ['--use-gl=angle', '--use-angle=swiftshader-webgl', '--enable-unsafe-swiftshader'] });
const page = await browser.newPage({ viewport: { width: 1280, height: 720 } });
page.on('console', m => { if (m.type() !== 'log') console.log(m.type(), m.text()); });   // ошибки шейдеров
await page.goto('http://localhost:5173/');
await page.waitForFunction(() => window.__frameReady === true);                           // флаг после первого render()
await page.locator('canvas').screenshot({ path: 'scene.png' });
const center = await page.evaluate(() => {                                                // дешёвая проверка «не чёрный кадр»
  const gl = document.querySelector('canvas').getContext('webgl2'); const p = new Uint8Array(4);
  gl.readPixels(gl.drawingBufferWidth >> 1, gl.drawingBufferHeight >> 1, 1, 1, gl.RGBA, gl.UNSIGNED_BYTE, p); return [...p];
});
console.log('center pixel', center);
await browser.close();
```

Контекст для кода three.js теперь даёт сам проект. `docs/llms.txt` в репозитории three.js — это «Instructions for Large Language Models». Он велит использовать import maps вместо старых CDN, по умолчанию `WebGLRenderer`, а `WebGPURenderer` с TSL — только для своих шейдеров и compute ([llms.txt](https://github.com/mrdoob/three.js/blob/dev/docs/llms.txt)). Соседний `llms-full.txt` весит 363 КБ, около 90 тыс. токенов, и его нужно читать фрагментами через Grep, а не целиком. Текущие версии: `three` 0.186.1, `@react-three/fiber` 9.8.2, `@react-three/drei` 10.7.9 ([npm three](https://www.npmjs.com/package/three)). Скилы CloudAI-X нацелены на ту же r186. Но каждый из них при вызове стоит 7–12 тыс. токенов [лаб.], поэтому ставьте выборочно. Зрелых скилов для WebGPU/TSL и GLSL нет, у всех меньше 25★. Официальный `@modelcontextprotocol/server-shadertoy` — MCP App, и в терминале его интерфейс не отрисуется. Оптимизацию glTF проще делать CLI-утилитами без MCP: `gltf-transform optimize input.glb output.glb --texture-compress webp` или `gltfpack -i scene.gltf -o scene.glb -cc -tc` (KTX2/BasisU), а потом снова загрузить модель и снять скриншот ([glTF-Transform](https://github.com/donmccurdy/glTF-Transform); [gltfpack](https://github.com/zeux/meshoptimizer/blob/master/gltf/README.md)). Для Gaussian splatting есть `@playcanvas/splat-transform`: фильтры `-N`, `-H` и экспорт в SOG или HTML-вьюер ([splat-transform](https://github.com/playcanvas/splat-transform)). Рендерер Spark в quick start закрепляет three 0.180, поэтому перед смешиванием с r186 проверьте peerDependencies ([spark](https://github.com/sparkjsdev/spark)).

## Хуки, субагенты и CLAUDE.md превращают проверку из просьбы в правило

Всё, что выше сказано про цикл «рендер → просмотр → правка», работает, только если Claude не забывает его выполнять. Документация Claude Code прямо говорит, что CLAUDE.md — это «context, not enforced configuration». Правила, которые должны выполняться всегда, относятся к хукам и разрешениям ([Memory](https://code.claude.com/docs/en/memory)). Ниже — проверенные по документации v2.1.303 ключи и собранные из них заготовки. Ни одна заготовка не прогонялась целиком, поэтому все они помечены `[выведено]`.

### Хуки запускают проверку сами, но картинку передают только путём к файлу

Хук возвращает Claude результат двумя способами. Первый — выход с кодом 2 и сообщение в stderr. Для `PostToolUse` это не отменяет правку («the tool already ran»), но Claude видит текст и исправляет ошибку. Второй — выход с кодом 0 и JSON на stdout: либо `{"decision":"block","reason":…}`, либо `hookSpecificOutput.additionalContext`. Предупреждение из хука, завершившегося с кодом 0, Claude не видит («Claude never sees stderr from a hook that exits 0»). `additionalContext` ограничен 10 000 символами. Писать его документация советует фактическими утверждениями, а не командами, иначе срабатывает защита от prompt injection. Stdout должен содержать только JSON: лишний `echo` из профиля shell ломает разбор ([Hooks reference](https://code.claude.com/docs/en/hooks)). Документированного способа приложить к ответу хука изображение нет. Рабочая схема такая: хук рендерит PNG и сообщает путь, а CLAUDE.md или скил велит прочитать превью. Медленные проверки вроде полного `tsc` или скриншота страницы не должны блокировать каждую правку. Для них есть `async`/`asyncRewake` («wakes Claude on exit code 2») или хук `Stop`, который срабатывает раз за ход. У `Stop` есть поле `stop_hook_active` против зацикливания и предел в 8 продолжений подряд. Ещё три особенности стоит знать. Матчер `Edit|Write` — точный список, а `Edit.*` уже регулярное выражение и захватит `NotebookEdit`. Хук на `Edit|Write` не срабатывает, если файл переписал Bash. В режиме `-p` хуки из закоммиченного `.claude/settings.json` выполняются даже в папке, которой вы никогда не доверяли ([Hooks reference](https://code.claude.com/docs/en/hooks); [Hooks guide](https://code.claude.com/docs/en/hooks-guide)).

```json
{
  "hooks": {
    "PostToolUse": [
      { "matcher": "Edit|Write", "hooks": [
        { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/post-edit-check.sh", "args": [], "timeout": 60, "statusMessage": "prettier + eslint" },
        { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/svg-preview.sh", "args": [], "timeout": 60, "statusMessage": "SVG → PNG" },
        { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/tsc-async.sh", "args": [], "asyncRewake": true, "timeout": 300 }
      ] }
    ],
    "Stop": [
      { "hooks": [ { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/ui-screenshot.sh", "args": [], "timeout": 90, "statusMessage": "Скриншот UI" } ] }
    ]
  }
}
```

```bash
#!/usr/bin/env bash
# .claude/hooks/post-edit-check.sh — формат и линт изменённого файла; ошибки Claude видит через exit 2   [выведено]
set -uo pipefail
FILE=$(jq -r '.tool_input.file_path // empty'); [[ -f "$FILE" ]] || exit 0
cd "$CLAUDE_PROJECT_DIR" || exit 0
case "$FILE" in *.ts|*.tsx|*.js|*.jsx|*.css|*.html|*.json|*.md) npx --no-install prettier --write "$FILE" >/dev/null 2>&1;; esac
case "$FILE" in *.ts|*.tsx|*.js|*.jsx)
  OUT=$(npx --no-install eslint --max-warnings=0 "$FILE" 2>&1) || { printf 'ESLint в %s:\n%s\n' "$FILE" "$(head -c 8000 <<<"$OUT")" >&2; exit 2; };;
esac
exit 0
```

```bash
#!/usr/bin/env bash
# .claude/hooks/svg-preview.sh — после правки *.svg: PNG-рендер и путь к нему в additionalContext   [выведено]
set -uo pipefail
INPUT=$(cat); FILE=$(jq -r '.tool_input.file_path // empty' <<<"$INPUT")
[[ "$FILE" == *.svg && -f "$FILE" ]] || exit 0
DIR=$(jq -r '.scratchpad_dir // empty' <<<"$INPUT"); DIR=${DIR:-"$CLAUDE_PROJECT_DIR/.claude/previews"}; mkdir -p "$DIR"
PNG="$DIR/$(basename "${FILE%.svg}").png"
LOG=$(resvg "$FILE" "$PNG" -w 512 2>&1) || { echo "resvg не смог отрендерить $FILE: $LOG" >&2; exit 2; }
NOTE=""; grep -q '@keyframes rule is not supported' <<<"$LOG" && NOTE=" Файл содержит CSS-анимацию; resvg отрисовал только статический кадр."
jq -nc --arg m "PNG-рендер 512 px файла $FILE записан в $PNG.$NOTE" '{hookSpecificOutput:{hookEventName:"PostToolUse",additionalContext:$m}}'
```

```bash
#!/usr/bin/env bash
```

`tsc-async.sh` устроен так же. Он запускает `npx --no-install tsc --noEmit -p .` и при ошибке печатает первые 60 строк в stderr с кодом 2. Благодаря `asyncRewake` Claude проснётся, даже если сессия простаивает. Добавьте `.claude/previews/` в `.gitignore`. Для Remotion аналогичный асинхронный хук запускает `npx --no-install remotion compositions`, чтобы поймать сломанную регистрацию композиций. Стоп-кадры при этом лучше оставить отдельным шагом, потому что они медленные. Завершается ли `compositions` ненулевым кодом на сломанном бандле, не проверено. Отладка хуков: `/hooks` показывает подключённые хуки, сам скрипт удобно проверять, подавая JSON через pipe, а `claude --debug` выводит подробности. Отключить все хуки разом можно через `--settings '{"disableAllHooks": true}'` ([Hooks guide](https://code.claude.com/docs/en/hooks-guide)).

### Субагенты забирают пачки картинок из основного контекста

Субагент — это файл `.claude/agents/<name>.md`. Обязательны только `name` и `description`. Полезные необязательные поля: `tools`/`disallowedTools`, `model`, `effort`, `skills` (подгружает полный текст скилов), `mcpServers`, `hooks`, `isolation: worktree`, `maxTurns`, `background`. Субагент получает только свой системный промпт, без системного промпта Claude Code. Опечатку в имени поля Claude Code молча игнорирует, найти её можно через `claude --debug` ([Subagents](https://code.claude.com/docs/en/sub-agents)). Для визуальной работы важны две детали. Встроенный в субагента `mcpServers` с Playwright держит описания браузерных инструментов вне основного контекста. Но allowlist `tools` отрезает и MCP-инструменты, если их не перечислить, поэтому для таких агентов используйте `disallowedTools`. Субагенты из плагинов игнорируют `mcpServers`, `hooks` и `permissionMode` ([Subagents](https://code.claude.com/docs/en/sub-agents)). Выгода считается просто. Двенадцать скриншотов по ~2,7 тыс. токенов — это ~32 тыс., а субагент вернёт таблицу примерно на тысячу. Делегировать вредно в другом случае: при итеративной подгонке («чуть больше отступ… теплее»). Каждый субагент стартует с нуля, а ваши вкусовые замечания остаются в основном потоке. Рабочая схема: основной поток правит, ревьюер проверяет на вехах. Ревьюеру документация советует велеть «flag only gaps that affect correctness or the stated requirements», иначе он найдёт недочёты и в безупречной работе ([Best practices](https://code.claude.com/docs/en/best-practices)).

```markdown
---
name: visual-reviewer
description: Сравнивает отрендеренный результат (скриншоты UI, рендеры SVG, кадры видео, 3D-рендеры) с эталоном или письменной спецификацией и возвращает список конкретных визуальных отличий по приоритету. tools: Read, Glob, Bash
model: opus
effort: high
maxTurns: 20
---

1. Сначала прочитай эталон, затем каждую фактическую картинку.
2. Мелкие детали вырезай ImageMagick (`magick actual.png -crop 600x400+0+0 crop.png`) и читай фрагмент.
3. Сравни: раскладку и выравнивание, шкалу отступов, типографику, цвета против токенов, иконки, состояния, обрезку, адаптивность.
4. Не больше 15 отличий, самые серьёзные первыми: | # | Область | Ожидалось | Получилось | Серьёзность | Вероятная правка |
5. Отмечай только то, что нарушает эталон или требования; вкусовых мнений не давай.
Последняя строка: VERDICT: MATCHES | MINOR_DIFFS | MAJOR_DIFFS.
```

Аудитор доступности строится так же, но с `disallowedTools: Write, Edit, NotebookEdit` и встроенным сервером `mcpServers: [{playwright: {type: stdio, command: npx, args: ["-y", "@playwright/mcp@latest"]}}]`. Сначала он работает по accessibility-снимку, скриншоты делает только для контраста и фокуса. Для пачек рендеров Remotion, Blender и SVG подходит `render-checker` с `background: true` и `model: sonnet`: он рендерит минимальный доказательный набор и сообщает только о проблемах [выведено]. Все текущие алиасы (Opus 5.5, Sonnet 5.5, Haiku 5.5) относятся к поколению 4.7+ и получают зрение высокого разрешения. Поэтому выбирать модель стоит по качеству рассуждений, а не по зрению. Opus подходит для реализации и ревью дизайна, Sonnet — для рутинных проверок, Haiku — для бинарных вопросов вроде «кадр чёрный?». Это экспертная оценка, официального сравнения нет ([Model config](https://code.claude.com/docs/en/model-config)).

### CLAUDE.md хранит команды проверки, а правила по путям — конвенции

### Свои скилы: короткий SKILL.md, детерминированные скрипты и A/B-прогон

Свой доменный скил — это короткий `SKILL.md`. В нём настойчивое описание от третьего лица («что делает и когда применять», главный сценарий первым) и нумерованный рабочий процесс с циклом рендер → проверка → правка. Описание и `when_to_use` вместе обрезаются на 1 536 символах ([Skills](https://code.claude.com/docs/en/skills)). Документация skill-creator прямо предупреждает, что Claude склонен «undertrigger» скилы, поэтому описания лучше делать «a little bit pushy» ([skill-creator](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)). Всё детерминированное — рендер, оптимизацию, измерения, извлечение кадров — выносите в `scripts/` и вызывайте через `${CLAUDE_SKILL_DIR}`. Скрипт исполняется, а в контекст попадает только его вывод. Свободу инструкций подбирайте по хрупкости операции: эстетические решения описывайте текстовыми эвристиками, а хрупкие шаги — «Run exactly this script» ([Platform: best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). У frontmatter есть две ловушки. С `paths:` скил подгружается сам только при работе с подходящими файлами, поэтому «нарисуй логотип» в новой сессии его не вызовет. `allowed-tools` действует только в ходе, который вызвал скил, но в `-p` применяется даже в папке без доверия ([Skills](https://code.claude.com/docs/en/skills)).

```markdown

description: Создаёт, правит и оптимизирует SVG-иконки, логотипы и иллюстрации этого репозитория, рендеря каждый черновик в PNG и проверяя его перед завершением. ### Автоматизация: `claude -p` решает, детерминированные инструменты исполняют
```

Для пакетов работает простая петля по `claude -p`. Нужные флаги: `--output-format json` и `--json-schema` (результат в `structured_output`), `--allowedTools` с `--permission-mode dontAsk` (разрешено ровно перечисленное, остальное отклоняется), лимиты `--max-turns` и `--max-budget-usd` («Spend can pass the cap, so leave headroom»). Для воспроизводимости используйте `--bare`: он пропускает автозагрузку хуков, скилов, плагинов, MCP и CLAUDE.md и требует `ANTHROPIC_API_KEY` ([Headless](https://code.claude.com/docs/en/headless); [CLI reference](https://code.claude.com/docs/en/cli-reference)). Принцип разделения ролей — «plan → validate → execute» из документации платформы. Claude решает, что вырезать и не испорчен ли рендер, а SVGO, ffmpeg, Remotion и Blender исполняют. Чисто детерминированную работу вроде `npx svgo -rf assets/icons -o assets/icons` модель вообще не должна делать. Внутри петли перенаправляйте stdin `claude -p` на `/dev/null`, иначе он съест список файлов из `while read`. Ту же защиту ffmpeg даёт `-nostdin`.

```bash
# Нарезка shorts: Claude планирует по SRT, jq проверяет план, ffmpeg режет   [выведено]
SCHEMA='{"type":"object","properties":{"cuts":{"type":"array","items":{"type":"object","properties":{"start":{"type":"number"},"end":{"type":"number"},"title":{"type":"string"}},"required":["start","end","title"]}}},"required":["cuts"]}'
for ep in transcripts/*.srt; do
  id=$(basename "$ep" .srt)
  claude -p "Прочитай $ep. Выбери 3 самодостаточных фрагмента по 30–60 с для вертикальных shorts; резать по границам предложений; время в секундах из SRT." \
    --allowedTools "Read" --permission-mode dontAsk --max-turns 5 \
    --output-format json --json-schema "$SCHEMA" < /dev/null > "plans/$id.json"
  jq -e '.structured_output.cuts | length > 0 and all(.end > .start and (.end - .start) <= 60)' "plans/$id.json" >/dev/null || { echo "плохой план $id"; continue; }
  jq -r '.structured_output.cuts[] | "\(.start) \(.end)"' "plans/$id.json" | while read -r s e; do
    ffmpeg -nostdin -y -i "raw/$id.mp4" -ss "$s" -to "$e" -c:v libx264 -c:a aac "out/${id}_${s%.*}.mp4"
  done
done
```

Визуальная регрессия в CI строится в два этапа. Сначала Playwright-тесты, затем `anthropics/claude-code-action@v1`, которому передают diff-картинки на разбор: что задумано в PR, а что регрессия. Workflow запускается только по путям интерфейса и, пока эталоны не обновит человек, оставляет проверку красной. Секреты GitHub в PR из форков не передаёт. Чтобы action мог оставлять инлайн-комментарии, `--allowedTools` должен явно назвать `mcp__github_inline_comment__create_inline_comment` ([GitHub Actions](https://code.claude.com/docs/en/github-actions)).

```yaml
# фрагмент .github/workflows/visual.yml   [выведено]
      - run: npx playwright test tests/visual || echo "VISUAL_FAILED=1" >> "$GITHUB_ENV"
      - uses: anthropics/claude-code-action@v1
        if: env.VISUAL_FAILED == '1'
        env: { GH_TOKEN: "${{ github.token }}" }
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          prompt: |
            Визуальные тесты Playwright упали. Для каждого *-diff.png в test-results/ прочитай соответствующие
            *-expected.png и *-actual.png, прочитай описание PR через `gh pr view` и классифицируй каждое
            расхождение как INTENDED или REGRESSION. Оставь ОДИН комментарий с таблицей. Файлы не меняй.
          claude_args: |
            --max-turns 25
            --allowedTools "Read,Glob,Bash(gh pr view *),Bash(gh pr comment *)"
      - if: env.VISUAL_FAILED == '1'

```

Варианты дизайна удобно делать параллельно в worktree. `claude --worktree hero-minimal`, `claude --worktree hero-bold` и так далее дают отдельные checkout'ы в `.claude/worktrees/<name>`. В `.worktreeinclude` перечислите `.env*`, а dev-серверам дайте разные порты. Потом субагент `visual-reviewer` сравнивает их скриншоты и ранжирует варианты. Для многих механических вариантов («перерисуй все 40 иконок новым штрихом») есть `/batch`: он раскладывает работу на 5–30 субагентов, у каждого свой worktree ([Worktrees](https://code.claude.com/docs/en/worktrees); [Best practices](https://code.claude.com/docs/en/best-practices)). Долгий локальный рендер удобно опрашивать через `/loop 10m …`. Ночные рендеры на GPU подходят для локальных scheduled tasks, а еженедельные визуальные аудиты репозитория — для cron в GitHub Actions ([Scheduled tasks](https://code.claude.com/docs/en/scheduled-tasks)).

### Разрешения: дешёвые проверки разрешены, необратимое спрашивает

Правила проверяются в порядке deny → ask → allow, и первое совпадение решает исход. Поэтому подходящее правило `ask` спрашивает, даже если более конкретное `allow` тоже подходит. Списки из разных файлов складываются, и deny на любом уровне побеждает ([Permissions](https://code.claude.com/docs/en/permissions)). Две тонкости меняют то, как пишут пресеты. Первая: правила `Read`/`Edit` не действуют на подпроцессы. Скрипт Python или ffmpeg с `-y` перезапишет «защищённый» файл, и настоящую границу даёт только `/sandbox`. Вторая: разрешение `blender -b … -P script.py` или `node script.js` фактически разрешает произвольный код. Разрешайте дешёвые проверочные команды. Дорогое и необратимое — финальные и облачные рендеры, обновление эталонов, push — оставляйте неперечисленным (тогда в `dontAsk` оно отклоняется) или под `ask` ([Permissions](https://code.claude.com/docs/en/permissions); [Sandboxing](https://code.claude.com/docs/en/sandboxing)).

```json
{
  "permissions": {
    "allow": [
      "Bash(npx prettier *)", "Bash(npx eslint *)", "Bash(npx tsc *)",
      "Bash(npx playwright test *)", "Bash(npx playwright screenshot *)",
      "Bash(npx svgo *)", "Bash(resvg *)", "Bash(magick *)",
      "Bash(ffprobe *)", "Bash(ffmpeg -nostdin *)",
      "Bash(npx remotion compositions *)", "Bash(npx remotion still *)", "Bash(npx remotion render * --frames=*)",
      "Bash(python3 -m py_compile *)",
      "Bash(curl -sf http://localhost:*)"
    ],
    "ask": [
      "Bash(npx playwright test * --update-snapshots*)", "Bash(npx playwright test * -u*)",
      "Bash(npx remotion lambda *)", "Bash(npx hyperframes cloud *)",
      "Bash(blender -b *)",
      "mcp__blender__execute_blender_code",
      "Bash(npm install *)", "Bash(git push *)"
    ],
    "deny": [
      "Read(./.env)", "Read(./.env.*)",
      "Edit(/tests/**/*-snapshots/**)", "Edit(/public/footage/**)",
      "Bash(rm -rf *)"
    ]
  }
}
```

Полный рендер `npx remotion render <id> out.mp4` здесь намеренно не перечислен. Правило `ask` на `npx remotion render *` задело бы и разрешённые превью с `--frames`, потому что ask побеждает allow. `blender -b` вынесен в `ask`, потому что с `-P` это произвольный Python. Если доверяете машине, перенесите его в `.claude/settings.local.json`. Запрет `Edit` на папки снапшотов не даёт Claude «починить» регрессию правкой эталона, а `ask` на `--update-snapshots` закрывает тот же путь через Bash [выведено]. Ответ «Yes, and don't ask again» сохраняется в `.claude/settings.local.json` ([Permissions](https://code.claude.com/docs/en/permissions)). Встроенный скил `/fewer-permission-prompts` по истории сессий предлагает allowlist для только читающих команд.

**Цифры первого отчёта нужно уточнить.** Snyk в ToxicSkills на 5 февраля 2026 года проверил 3 984 скила из ClawHub и skills.sh. Подтверждаются две цифры: у 534 скилов (13,4 %) есть хотя бы одна критическая проблема, у 1 467 (36,82 %) — дефект любой степени. Но **подтверждённых вредоносных нагрузок — 76**: кража учётных данных, бэкдоры, эксфильтрация, причём 8 из них на момент публикации были ещё активны в ClawHub. Заголовок поста Snyk и пересказ AgentGuard, где 1 467 названы «malicious payloads», противоречат телу самого исследования. В той же выборке у 10,9 % скилов ClawHub зашиты секреты, а 2,9 % скачивают и исполняют удалённое содержимое. Разбивки отдельно по skills.sh нет ([Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/); [разбор](https://github.com/FlorianBruniaux/claude-code-ultimate-guide/blob/main/docs/resource-evaluations/snyk-toxicskills-evaluation.md)). Отчёт Koi ClawHavoc обновлён 16 февраля: при росте ClawHub с 2 857 до 10 700+ скилов число вредоносных выросло с 341 до 824. Нагрузки — Atomic macOS Stealer и кейлоггер для Windows в запароленном ZIP, приманки — криптокошельки, боты Polymarket и тайпсквоттинг ([Koi](https://koi.ai/blog/clawhavoc-341-malicious-clawedbot-skills-found-by-the-bot-they-were-targeting); [The Hacker News](https://thehackernews.com/2026/02/researchers-find-341-malicious-clawhub.html)). Обе находки сосредоточены на ClawHub, реестре OpenClaw, а не на маркетплейсах Claude Code. Подтверждённого вредоносного плагина в `claude-plugins-official` не найдено. Но формат скилов тот же, и skills.sh входил в выборку.

Специфичные для Claude Code угрозы 2026 года связаны с конфигурацией, а не со скилами. Mitiga Labs показала, что `postinstall` вредоносного npm-пакета может переписать `~/.claude.json` и пустить MCP-трафик через прокси атакующего, а OAuth-токены лежат там открытым текстом. Anthropic признала это «out of scope», патча нет ([mitiga.io](https://mitiga.io/blog/claude-code-mcp-token-theft-mitm); [SecurityWeek](https://securityweek.com/claude-code-oauth-tokens-can-be-stolen-through-stealthy-mcp-hijacking)). Проверка в контейнере подтвердила смежное. Значение `--header` хранится в `~/.claude.json` открытым текстом, хотя CLI печатает `[REDACTED]`. `add-json --scope project` записывает буквальный ключ в коммитимый `.mcp.json` [лаб.]. Уязвимости доверия к репозиторию — TrustFall, CVE-2025-59536 и CVE-2026-21852, утечка исходников через `enableAllProjectMcpServers` — описаны как исправленные ([Dark Reading](https://www.darkreading.com/application-security/trustfall-exposes-claude-code-execution-risk); [dev.to](https://dev.to/sattyamjjain/cve-2026-21852-how-enableallprojectmcpservers-leaks-your-entire-source-code-5ddc)). Самое важное для этого набора инструментов — **ContextCrush (CVE-2026-75130)**, опубликованная 18 августа 2026 года. Custom Rules в Context7 доставлялись агентам без очистки, и отравленные правила библиотеки могли во время обычного поиска документации вытащить учётные данные из env-файлов и удалить файлы. Оценки расходятся: CVSS 3.1 — 9,0, CVSS 4.0 — 6,4. Статус исправления тоже противоречив: Mend называет уязвимыми версии ниже 2.1.3, другие источники пишут, что патча нет ([Infosecurity Magazine](https://infosecurity-magazine.com/news/contextcrush-ai-development-tools); [Mend](https://mend.io/vulnerability-database/CVE-2026-75130/); [OpenCVE](https://app.opencve.io/cve/CVE-2026-75130)). Практически: обновите Context7, не полагайтесь на правила непроверенных библиотек и там, где есть документация из пакета фреймворка, предпочитайте её.

Модель угроз из документации не изменилась. Плагин «can execute arbitrary code on your machine with your user privileges». Хуки, MCP- и LSP-серверы работают вне песочницы и вне правил разрешений ([Plugin security](https://code.claude.com/docs/en/plugins/security)). В режиме `-p`, в Agent SDK и в облачных сессиях серверы из `.mcp.json` подключаются без вопроса, а `allowed-tools` проектного скила действует даже в папке без доверия ([Claude Code: MCP](https://code.claude.com/docs/en/mcp); [Skills](https://code.claude.com/docs/en/skills)). Проверка добавила к этому ещё одно: `claude plugin install` из терминала ставит плагин сразу, без панели и подтверждения [лаб.]. В визуальных инструментах свои риски. Почти все мосты к DCC открывают локальный сокет без аутентификации. У Blender MCP и community-сервера SketchUp это один и тот же порт 9876, а авторы Fusion-сервера пишут «never bind to 0.0.0.0» ([sketchup-mcp](https://github.com/mhyrr/sketchup-mcp); [fusion360-mcp-server](https://github.com/faust-machines/fusion360-mcp-server)). Скрипты Resolve 21.1 получают тот же доступ к диску и сети, что и ассистент ([nordlys.io](https://nordlys.io/en/blog/davinci-resolve-mcp-ai-asistent)). Blender Lab рекомендует запускать MCP в виртуальной машине ([voyager.so](https://voyager.so/blog/blender-mcp)). Penpot и Roblox позволяют агенту исполнять код прямо в открытом файле. Копия ui-ux-pro-max в одном из реестров получила 24/100 в аудите на prompt injection и безопасность shell ([tarai.dev](https://tarai.dev/en/skill/ui-ux-pro-max/)). AntV по умолчанию отправляет данные графиков на сервер Alipay, а TwelveLabs и video-use загружают материал в облака. Телеметрию выключайте явно: у Chrome DevTools MCP флаги `--no-usage-statistics` и `--no-performance-crux`, у TanStack CLI `TANSTACK_CLI_TELEMETRY_DISABLED=1`, у `npx skills` и MCP for Blender `DISABLE_TELEMETRY` ([Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp); [vercel-labs/skills](https://github.com/vercel-labs/skills)).

Порядок проверки перед установкой складывается из того, что реально проверено. Сначала `npx skills add <repo> -l` и чтение SKILL.md со скриптами: ищите `curl | sh`, «предварительные» загрузки, обфускацию, обращения к `~/.ssh`, `.env` и профилям браузера. Для плагина выполните `claude --plugin-dir <клон> plugin details <name>`: это опись и стоимость без запуска MCP [лаб.]. Затем просмотрите `hooks/hooks.json`, `.mcp.json`, `bin/` и `allowed-tools`. Автоматический сканер `uvx snyk-agent-scan@latest ~/.claude/skills` требует `SNYK_TOKEN`, и запускать его нужно в одноразовом окружении, потому что «Scanning MCP configurations can execute commands» ([snyk/agent-scan](https://github.com/snyk/agent-scan)). Закрепляйте версии (`owner/repo#tag`, `pkg@x.y.z`) и помните, что `uvx` без версии навсегда остаётся на первой скачанной. Автообновление у сторонних маркетплейсов оставляйте выключенным: у официальных оно по умолчанию включено, у сторонних выключено ([Install plugins](https://code.claude.com/docs/en/plugins/install)). Секреты держите только в `${VAR}`. Периодически просматривайте, какие серверы записаны в `~/.claude.json` (`jq '.mcpServers, (.projects[]?.mcpServers)' ~/.claude.json` [выведено]). Для генерации и публикации ставьте подтверждение человеком. Это может быть elicitation у принтерного MCP, `OBS_MCP_CONFIRM_LIVE=true` у OBS или PreToolUse-хук на инструмент загрузки на YouTube.

## Выводы

Главный урок второго раунда — проверку тоже нужно проверять. Почти все найденные ошибки сидели не в выборе инструментов, а в командах самопроверки: конфиг SVGO тихо ломал те самые анимацию и доступность, которые должен был беречь; контакт-лист рисовал чёрные плитки; многоскиловая установка теряла скил с кодом 0. Ошибка самопроверки опаснее ошибки генерации, потому что даёт ложное «всё в порядке». Это то же явление, что и молчаливые «успешные» рендеры HyperFrames. Поэтому ритуал из этого отчёта — временный `HOME`, `-l`, `plugin details` через `--plugin-dir`, один реальный прогон на тестовом файле — стоит выполнять при каждом обновлении набора, а не один раз. Второй сдвиг — в бюджете. Узким местом становится уже не число MCP-серверов (их гасит tool search), а постоянный список скилов и стоимость их тел. Вендоры отвечают на это переходом к документации и скилам, которые поставляются с пакетом под точную версию (Next.js, React Router, TanStack Intent, Angular). Скил превращается в обычную зависимость с версией, lock-файлом и обновлением вместе с библиотекой, и относиться к нему стоит именно так.

Третья закономерность касается 3D и монтажа. Официальные MCP пришли в Resolve, Unreal, Unity, Roblox, Rhino, Cinema 4D и SketchUp, но зрелость у них разная. Часть официально поддерживает только Claude Desktop или claude.ai (Cinema 4D, SketchUp, Affinity), часть остаётся experimental или страдает от багов подключения (Unreal, Unity), а Resolve требует платную Studio. Бенчмарки же показывают, что доверять агенту можно там, где результат измерим: раскладка, артикуляция, CAD с габаритами, громкость в LUFS. Там, где нужно «как на фото», «приятно играть» или «красиво», доверять нельзя. Отсюда практическое правило выбора на 2027 год. Сначала спросите, можно ли измерить результат командой. Если можно — ставьте скил плюс CLI и пишите хук. Если нельзя — оставляйте человека в цикле и давайте ему, а не модели, финальный скриншот.
